# 评价分析

Web和CLI共用service，后台worker独立进程复用TaskEvents日志与进程身份，不持有浏览器资料锁。rules负责版本化提示、严格编号与初评/追评原文验证、同义映射及整数统计；planning按输入与预计输出合并评价并固定完整发送清单，纯本地计算。存储在infrastructure/storage/analysis_store，当前0013/schema_v13沿用原五表，仅更新恢复语义原生备注。

GET和导出只读；创建前明确费用并保存整批快照，最多1000条，不发送昵称媒体。调用先落库inflight再联网，响应收据先落本机后事务写入原始返回和校验分类；失败停止，恢复先补写收据，跳过已有阶段，无自动重试。预算按字节+输出量保守预留，不估价，未知用量单列。密钥只在执行时读本机配置，不进入任务参数、请求快照或日志。

主题词典未覆盖的名称保留原名，UI提示复核，不假称语义去重完整。人工修订原结果不变，修正及报告都保留版本；本地重统计移除旧综合文字，不重新调用AI。示例只在独立库/模拟AI验证，真实付费验收待用户明确范围。见使用指南和评价分析实施记录。

计划版任务rules.schema_version=2、parameters.budget_version=2，分类请求使用JSON模式；旧无plan任务继续原10条/18000字符及输出4096的规则。新版预算确认用量后释放未用预留，报告额度提前保留；未知用量不释放。追加额度须明确计费确认并追加budget_history，原分组/提示不变。报告schema_version=2另记report_complete与unprocessed_count。完整协议维护在数据库字段取值说明，禁止改变JSON含义而不更新文档。

2026-10-30新提示版本reviews-v3，JSON结构仍兼容2/1。validation纯本地逐条检查、记录全部问题及有界规范化，POLICY变化必须递增版本。旧失败返回recover_saved不创建客户端或进程，原调用原文/状态不改写；结果与审计在同任务行锁内保存，digest保证重复恢复不新增。finish_call在线部分校验失败也保留有效条目，invalid不等于所有条目都无效。补处理在费用确认后按当前缺失编号另存不可覆盖清单，原plan保留；Web要求有效计划指纹，CLI resume --preview只读。机器通过不代表语义或人工复核通过。
