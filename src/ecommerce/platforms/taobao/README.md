# 淘宝搜索与详情页适配

主图采集已接入 `detail_images.py`：`taobao detail --input "商品ID或详情链接" --main-images` 直接读取页面 `window.__ICE_APP_CONTEXT__.loaderData.home.data.res.item.images`，缺失时使用已适配的 `res.componentsVO.headImageVO.images`。核对商品ID，以及与 `#picGalleryEle` 缩略图对应的实际数量、来源和顺序；排除视频封面及参数入口，不点击/悬停切图，不依赖当前大图状态，不改写链接。两份数据同时存在时均须对应，缺失或冲突转人工，不自动切回旧点击流程。业务层按1至N保存到商品目录 `1-1主图/`，合并统一 JSON；少于或超过五张均按实际数量采集。逐张保存历史及最后尝试，来源完全一致且文件校验通过时可在下次命令中复用未完成批次的成功项，全部完成才整批发布。与 `--video` 可组合使用。

详情入口已接入 `detail.py`：纯数字 ID 使用固定淘宝地址，详情 URL 校验后按原链接打开；统一由 `open_detail` 在传入页面执行单次导航，并通过现有验证守卫核对目标 ID。CLI 为 `taobao detail --input "商品ID或详情链接"`，不传功能参数时默认采集全部已实现项目；显式指定功能时仅执行所选项目。只指定 `--video` 时采集主图视频：`detail_video.py` 仅在 `#picGalleryEle` 中检测首个主图视频；有视频读取实际播放器地址，确认无视频才返回并跳过，未知结构或地址未加载转人工。视频下载和本地结果保存在采集业务模块，其余步骤见下方对应说明。

后台输入通道关闭时仍保留暂停任务，可用 `taobao continue` 反馈当前提示；原生弹窗使用 `taobao confirm`/`taobao cancel`，不会用通用继续代替决定。

后续采集实现与验收须遵循 [淘宝采集执行约定](../../../../docs/淘宝采集约定.md)。保护组件已具备可配置间隔、分段等待、人工复核和任务暂停/停止能力，搜索模块仍需登记商品请求规则并适配真实页面。

详情SKU步骤已接入 `detail_skus.py`：唯一 `#skuOptionsArea` 内按规格组、选项动态枚举，读取完整标题与销量原文，Playwright单次选择后核对选中状态、数量1、价格加载、相关请求完成和稳定状态。多组组合重新检查联动，隐藏副本及区域外推荐不计入。`data-vid`只作规格值标识，正整数SKU ID仅采页面明确提供的标识，缺少时保留未提供状态；不按名称、负数规格值或禁用状态删除选项。缺货须有明确文本或库存为0的证据，仅禁用不能推断缺货，保存禁用证据及价格缺失原因。图片只采用页面提供的规格图片或核对为同资源的当前大图，实际下载、进度、复用及发布由采集模块负责；价格逐项记录本轮核对时间。未知结构、数量不符、可选价格未确认或请求失败转人工，不自动重放点击。业务模块只有确认孤立不可选警告且其余组合/价格/图片均已处理时，才允许后续流程继续，SKU仍部分完成。入口 `taobao detail --input "1050158363561" --skus`，列表循环待后续接入。

`detail_parameters.py` 已适配动态参数：只识别唯一可见 `.paramsInfoArea`，`emphasisParamsInfoItem--` 的名称在SubTitle、值在Title，普通 `generalParamsInfoItem--` 则相反。字段名及数量不写死；完整原文、同名项、单位和顺序保留。参数页签定位、模块滚动及已观察的展开入口均通过现有守卫执行，展开不重放；未知参数内容、加载中和明确空态分开。由采集模块合并 `parameters` 分区并留存原始HTML和诊断资料，入口 `taobao detail --input "1050158363561" --parameters`。其他新布局仍需复核适配，不承诺识别所有未知结构。

图文详情图片DOM在 `detail_description.py`：核对唯一“图文详情”标题和 `#imageTextInfo-container`，只读取模块内实际图片，逐段加载至末尾后固定完整有序列表。懒加载属性只作加载核对，下载采用真实 `currentSrc/src`，不推测资源地址。页签和展开入口单次操作，沿用验证守卫；空白未加载、明确无图及iframe/背景图未知结构分开。业务模块按数字发布到商品 `详情图/`，记录JSON、原HTML、逐图进度和历史，入口 `taobao detail --input "1050158363561" --detail-images`，可与已有步骤组合。


评价概览已接入独立 `--review-summary`：`detail_review_summary.py` 动态读取用户评价数量、好评率及时间范围、总结标签和对应计数，保留模糊数量原文及下界；仅保存概览HTML和商品JSON `review_summary` 分区，保留历史。不打开全部评价，不采集逐条评论；后续需另行确认。未知结构及验证沿用人工暂停。详见使用指南和详情页采集字段清单。


逐条评价已接入 `--reviews`，默认100条有效记录，`--reviews --all`取消上限。`detail_reviews.py` 读取独立评价侧栏、在列表内滚动，动态保存正文/时间/SKU/追评和买家媒体链接；精确模板好评不占名额，无评价、加载停滞、到达末尾及达到上限分别记录。商家回复不采集，媒体不下载。逐批SQLite事务保存，导出JSON/CSV后整批发布，保留历史和中断明细；身份ID缺失时记录指纹去重的不确定性，不宣称精确辨认所有匿名记录。完整规则见使用指南。


问大家（--questions）已接入正式详情流程，默认50个问题、每题回答不限；--all取消问题上限，与--reviews组合时同时取消两者上限。独立侧栏逐题展开、先存后滚、预览不重复计数、短回答保留；明确无问答/无回答与加载异常分开。平台DOM适配在detail_questions.py，业务模块同名，SQLite逐批进度及JSON/CSV按商品ID保存至问大家目录，总JSON questions分区保留既有资料。逐题间隔及定期休息可配置，守卫异常等待人工明确继续，发布回滚和历史规则见使用指南。
