# 评价提示词 V1.2 剩余问题与收尾方案

日期：2026-10-30。状态：**仅提案，待用户确认后执行**。前置[V1.2复测](评价提示词V1.2复测记录.md)已完成4次请求；本文件不自动授权V1.3、追加费用或正式接入。

## 当前判断

提取的七项集中问题多数已有改善，可读报告已经生成。但“引文存在”不等于“推理成立”，精确编号也没有阻止自然语言写错归因。继续堆提示词不能保证消除全部错误，建议本轮停止自动改版，先由用户查看报告内容价值，再确认必要的程序收尾和人工复核边界。

| 剩余问题 | 判断归属 | 建议的处理 |
|---|---|---|
| 完整p2引厚实，却推到不量少；p1把评价差异说成款式客观差异 | AI语义超出依据，程序关联存在并非语义证明 | 反证逐项对应支持属性，不能匹配时保留“待核对”，不参与确定结论；关键反证由人核对原文后采用 |
| 阶段data_issues误写696，实际694 | AI自由文字源编号错误；当前自由文字契约缺少程序验证 | 来源编号、缺失项和资料问题由程序从结构化flags/pending/issues生成，模型只说明影响，不再自由重写身份；保留版本和原返回 |
| 原统计引用无关联、推断引用类型错误 | AI输出不合格，现有程序局部隔离已有效 | 保持严格检查/局部保留，不放宽或补造；在报告中清楚说明被隔离内容，不让整份有效报告消失 |
| 外观印象/转述被当核心事实疑点 | 提取标注与统计含义边界需明确，非接口故障 | 区分“表达了什么”与“性能是否已验证”；先讨论规则，再调整独立契约/统计，不能把转述当已验证功能 |
| 多数/最集中等概括、引文偏宽 | 内容表达与排名依据不足 | 没有程序聚合/排名依据则使用定性表述并标局限；不靠数字正则宣称语义全检 |

## 建议下一步范围

1. 先阅读已生成的完整样例，确认报告对竞品研究和现成款拿样是否有帮助；不调用AI。优先核对两条选品方向、成立条件、反证、经营资料缺口和放弃条件，表达小问题单列。
2. 若认可内容价值，再单独批准“程序负责资料身份与范围、人工确认关键反证”的收尾实现。保留原返回、派生版本、复核意见和采用状态，避免改原文掩盖错误。先本地离线及已有返回回放，无需默认再次付费。
3. 完成收尾并确认报告后，另出正式Web/MySQL接入方案，明确新旧任务/报告兼容、版本与表字段、报告入口及批次关系。本轮不直接覆盖reviews-v3或旧报告。
4. 新商品泛化另设小范围样本：至少包含不同产品、负面/转述/空白/追评等边界，次数和预算重新确认。当前16条目的性样本不足以证明通用可靠。

## 有限收尾标准

来源身份与范围由程序保证；无依据推断不能作为已确认选品事实；有效内容可读、可追溯，格式问题局部隔离；用户可明确区分事实、假设、待核对与已采用。满足这些边界后进入有人复核的小范围使用，不要求所有文字完美，也不自动多轮付费改提示。

当前只完成报告上的助手疑点说明，未实施本提案的程序资料生成、人工采用流程或正式接入。此提案不得被理解为已解决剩余语义问题。
