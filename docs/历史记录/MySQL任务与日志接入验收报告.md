## 2. 已接入的运行行为

普通进度、现有 logging、异常和人工处理提示写入统一事件；终端继续输出，`workspace/logs/run.log` 继续追加，原淘宝 JSONL 也保留。人工反馈只记录受控决定，不录制输入原文。

任务操作先写本地持久流水，再由小容量后台通道补写 MySQL；积压留在磁盘，内存队列只负责唤醒。确认位置在数据库提交之后推进，提交回执丢失可安全重试。同一事件键内容不同会报冲突；数据库已结束的任务不会被后来的进度或不同结束操作覆盖。

断库时在平台检查点等待，停止入口通过本地描述核对资源、进程编号和进程启动时间，不依赖数据库在线。继续、确认不能绕过存储等待。业务结束但结束记录尚未入库时，返回“实际业务结果＋待入库”，不报已保存成功。恢复仅补写数据，不重放浏览器动作。

恢复失效任务前持有资源锁，并核实原进程已失效；仍存活的任务、其他资源任务、历史导入任务和无法确认归属的任务不会被批量改为中断。

历史导入以固定快照、稳定来源键及内容指纹核对；整批事务成功后发布，未提交根记录不进入正常查询。原文件追加时只导新增记录，重复输入不新增业务行，同源异文整批回滚。切换后只使用切换前快照复核，不重新扫描已经追加的实时 `run.log` 和淘宝事件，避免重复入库。
