# 北京时间统一调整说明

用途：记录2026-10-23的0002时间迁移；该版本号为当次迁移目标。当前模型0003_search_origin继续沿用北京时间，不再次偏移；最新字段见[字段字典](../数据库字段字典.md)。

2026-10-23，用户确认数据库表、命令行和网页统一使用北京时间。正式库 `taobao_automation`、独立库 `taobao_automation_verify` 已升级至 `0002_beijing_time`。

## 统一后的规则

- 全部 `DATETIME(6)` 字段直接保存北京时间（固定 UTC+08:00），在数据库客户端打开表即可查看，无需手动加八小时。
- 命令行及接口的结构化时间带 `+08:00`；终端、run.log 和网页按同一北京时间显示，不依赖主机时区、不重复偏移。
- 外部时间必须带明确时区，写入前转换为北京时间；未知时区的历史时间继续留空，不能猜测或用零值代替。
- `time_raw`、来源 JSON、原文件及幂等指纹保留原文。它们可能含 UTC 或其他时区，用于溯源，不是数据库规范时间字段的口径。
- 旧记录通过新增迁移转换一次。`0001` 首版迁移和模型保持冻结，不能改写历史迁移或反复给原记录加八小时；仅修改 MySQL 服务器时区不能转换既有 DATETIME 数据。

## 升级和查询

先结束正在运行的登录、采集或发布任务。升级命令会持有两平台浏览器资源锁，迁移还会拒绝存在未结束任务的数据库。MySQL备注变更先完成；随后时间数据与迁移版本在同一事务内提交，失败可以安全重试。

在新 CMD 中使用以下完整示例；密码沿用 Windows 当前用户环境变量，不写进命令参数：

```cmd
set "TAOBAO_PROJECT=D:\VSCodeProject\taobao_automation_system"
cd /d "%TAOBAO_PROJECT%"
"%TAOBAO_PROJECT%\.venv\Scripts\python.exe" "%TAOBAO_PROJECT%\main.py" database upgrade
"%TAOBAO_PROJECT%\.venv\Scripts\python.exe" "%TAOBAO_PROJECT%\main.py" database check
"%TAOBAO_PROJECT%\.venv\Scripts\python.exe" "%TAOBAO_PROJECT%\main.py" tasks
"%TAOBAO_PROJECT%\.venv\Scripts\python.exe" "%TAOBAO_PROJECT%\main.py" logs --task-id 88ad7e8c92b64349abbb02ddf91e0aa3 --limit 100
```

`upgrade`执行缺少的迁移；两库已经完成本次升级，无需再次转换。`check`只读核对版本、原生备注和约束。`tasks`查看任务时间；`logs`按完整任务编号核对日志，时间筛选使用例如`--since "2026-10-23T15:00:00+08:00"`，对应的UTC时间输入仍能筛到同一时刻。

在数据库客户端刷新后执行以下只读查询即可查看本次四条任务。无需`DATE_ADD`或另外设置客户端时区：

```sql
SELECT id, name, status, started_at, finished_at, message
FROM taobao_automation.tasks
ORDER BY started_at;

SELECT task_sequence, occurred_at, recorded_at, event_type, message
FROM taobao_automation.task_events
WHERE task_id = '88ad7e8c92b64349abbb02ddf91e0aa3'
ORDER BY task_sequence;
```
