# 评价分析记录页面整理

日期：2026-10-31。用户批准整理标题/返回、筛选/操作、最近报告和记录表，统一控件样式并适配手机；本轮仅整理显示，不改变批次筛选、调用或数据保存流程。

## 原因与实现

原历史模板没有引入review_analysis.css，也没有为GET表单及分析按钮设置布局；全宽公共选择控件后面的按钮自然换行，最近报告链接又混在普通段落里，导致堆叠和拥挤。模板改为独立ra-history-page，显式加载模块布局；桌面批次框最大420px，“查看”紧邻选择框，“分析评价”在右侧对齐，手机选择框一行、两个按钮并排。标题区保留商品/范围说明并单独安排“返回评价明细”。

最近成功报告使用现有ui-source-card浅色公共卡片，元信息和“查看报告”按钮分开排布；没有成功稿时沿用原服务返回的已保存部分结果，标题及按钮明确“部分结果”。失败和活动提示继续保留，不覆盖已有成功报告。记录表补状态标签与统一按钮；已有报告为“查看报告”，无报告的活动任务为“查看进度”，其他未生成报告任务为“查看任务”，避免把失败任务说成已有报告。

时间仅在历史模板使用strftime显示到秒，原DATETIME微秒及报告来源不改。来源数量对V6仍是本批来源数，旧版本仍保留原已处理/来源口径，不改成全部已分析。表格设最小宽度和独立滚动容器，小屏不撑开整个页面，可键盘聚焦滚动。颜色、字号、圆角、按钮及状态视觉使用form_controls，review_analysis.css只维护布局/宽度/排列/换行。

## 功能与数据边界

没有修改history_page、存储查询、路由校验、快照、提示词、版本、付费确认或执行器。批次下拉只有点击“查看”才应用，“分析评价”继续绑定当前已应用批次；全部批次范围不出现分析按钮。空记录、旧成功优先、最新失败/部分结果、活动任务、进程已结束提示及最近100条限制沿用原规则。打开分析弹窗只读原预览，取消不创建任务；未自动点击开始分析。

数据库仍0018_report_checks，不改DDL、迁移、原生备注、字段取值或JSON。本轮两库各32业务表数量及有序行SHA256前后一致，业务新增/修改/删除0，真实AI调用0。未恢复旧任务或修改报告、来源、预算与用量。
