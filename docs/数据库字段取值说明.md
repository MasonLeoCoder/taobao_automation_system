## 通用取值规则

| 类别 | 填写及理解 |
|---|---|
| SQL NULL | 未提供/未知/不适用按具体字段区分，不一律解释成失败、0或确认无数据 |
| 空字符串、空数组、空对象 | 空字符串不是状态自动兜底；[]是明确保存的空列表；{}是明确保存的空对象；与未给分开 |
| JSON null | JSON字面null与SQL NULL分开；当前search_options的Python None写SQL NULL，其他23个旧JSON列默认写JSON null，读取都可得到None，详见下方实际查询 |
| 布尔 | 1/true是、0/false否；可空布尔NULL为未知/未给，不当false |
| 主键/外键 | 内部id可不连续；外键填已存在目标主键并满足商品/批次/模块/任务复合归属 |
| 平台编号 | 字符串保留前导零、不转浮点；淘宝商品当前1～25位数字且非全0 |
| 数量/位置 | 计数0与未知NULL分开，位置通常从1开始；格子位置与有效商品序号分别保存 |
| 价格 | 精确DECIMAL，常用(20,6)，最多14整数位/6小数位；结合币种、首单/补贴等口径，未知不是0 |
| 时间 | MySQL DATETIME(6)直接存北京时间UTC+08:00；CLI/API带+08:00；外部时间须有明确时区再转换，time_raw/日期原文/原文件保留来源 |
| 哈希与幂等 | 路径/内容/范围/业务源/持久操作各自规范化，不互换；补写沿用同一持久身份 |
| 预留能力 | image/search_input_image仅图片搜索契约；平台功能未实现，取值登记不代表人工验收通过 |

### JSON空值的当前实际写入口径

24个JSON字段中，仅collection_batches.search_options显式none_as_null=True，其Python None写SQL NULL；其余23个旧JSON字段使用默认none_as_null=False，Python None写JSON字面null。SQLAlchemy读取两者都可得到None，普通客户端也可能显示近似空值，必须查询区分。

原生备注中“SQL NULL表示源未提供”是设计说明；上述旧列的当前写入行为存在差别，本文按实际代码及正式库核对结果分别登记。本次精简不改变剩余JSON列的空值写入口径；若以后统一JSON空值，需要另行设计并同步迁移与写入规则。

本轮真实例子：批次2的completion_evidence IS NULL为0，JSON_TYPE为字符串NULL，即JSON null；search_options IS NULL为1，JSON_TYPE返回SQL NULL，即SQL空值。

```sql
SELECT id,
       completion_evidence IS NULL AS evidence_is_sql_null,
       JSON_TYPE(completion_evidence) AS evidence_json_type,
       search_options IS NULL AS options_is_sql_null,
       JSON_TYPE(search_options) AS options_json_type
FROM taobao_automation.collection_batches
WHERE id = 2;
```

### tasks.status与任务名称

| 值 | 中文含义 | 填写/判断规则 |
|---|---|---|
| running | 正在执行 | 已创建任务；保留浏览器等待查看时也可能仍在运行 |
| succeeded | 执行成功 | 执行器成功结束并填写finished_at；不替代用户人工验收 |
| failed | 执行失败 | 未处理的业务异常或执行错误 |
| cancelled | 用户取消 | 用户停止/中断，不能标成功 |
| needs_attention | 需人工处理 | finished_at为空可为等待；有时间可为本次以需人工处理结论结束 |

origin=live实时、historical历史导入；历史任务没有当前进程归属，不参与实时恢复。owner_pid与进程启动时间一起核对。

当前入口名：account.taobao.login/check为淘宝登录/检查；account.login/check为千牛登录/检查；collection.taobao.search独立搜索；collection.taobao.collect列表采集；collection.taobao.detail.open详情入口及所选模块；product.open/product.submit打开发布页/提交商品。字段为业务字符串，后续新增入口必须登记。

真实实例：任务538c46e0e87045dd97a33bd423766dec在保存快照时status=running、finished_at=NULL、last_event_sequence=37，8条商品已经保存。这是历史核对时点，不声明浏览器此刻状态。

### task_events.details与时间依据

- operation_fingerprint为持久操作规范化SHA-256；event_key为幂等身份。补写沿用原身份及原内容。
- collection_saved含snapshot_sha256/target/target_id/issues。真实日志id=156、task_sequence=35、batch_id=2，target=collection_batches、target_id=2。
- 守卫保留脱敏time/task_id/event/state/step/progress，progress可有keyword/page_number/collected/target；阻断含kind/location/source/frame_location、截图及诊断。kind按来源，如tab标签、network网络、login登录、inspection无法检查、manual主动暂停、native原生弹窗、native_done弹窗已决定、resume_check恢复检查、business业务核对、operation动作异常，以及检测器的验证/弹窗类别。
- 2026-10-26主图业务核对失败时可附`check_details`对象，来源为当前同次画廊快照；含target_item_id、data_item_id、ssr_item_id、thumbnail_count、source_counts及comparisons。source_counts按完整页面数据路径记录数量；comparisons逐项含source_path、position（图片顺序）、slot_index（原缩略图位置）、thumbnail_url、image_url、same_origin_asset（仅忽略已确认crop裁切标记后是否同一资源）、exact_asset_match（忽略缩略图压缩后缀、保留裁切标记时是否相同）。诊断地址删除查询参数、片段和账号信息，不保存Cookie。下载前后清单变化时，check_details含target_item_id及expected_images/current_images；每项为slot_index、asset，asset为域名/目录/资源文件名的三元素数组。其他阻断可不提供此键；它是日志上下文，不改变采集状态或自动放行。人工继续后的业务复核失败仍为business，保留具体原因，不统一改成登录故障；旧resume_check事件不回写。
- session_halted的reason来自导致退出的NeedsAttention异常，保留前先经日志脱敏；仅保存原因，不执行继续、重放或跳过。修复前通用保留现场分支也会记input_unavailable，不能只凭旧事件代码推断真实终端输入丢失；例如任务dfd4eff50123420fb52619b79d279503最终message为“本地事件确认文件无法核对，请保留现场；未重置或跳过记录”。其视频批次5已保存，主图批次6为interrupted且仅4/5张；SKU等6步骤not_run，旧参数有效批次仍4。2026-10-24已修正该通用分支：后续异常保留现场记录session_halted及needs_attention状态，原历史事件不改写。
- 人工决定decision按调用处记录受控值，不保存输入原文；历史可含source_record/source_fingerprint/source_kind/relative_path/record_key，不明时间文本可有time_zone_unknown/task_link_unknown=true。

### collection_batches.stop_reason、派生与发布

| 原值 | 中文含义 |
|---|---|
| collecting | 正在采集的进度原因 |
| limit_reached | 达到上限 |
| no_reviews / no_questions | 明确无评价 / 问题 |
| end_of_list | 明确列表末尾 |
| folded_visible_end | 可见评价已到末尾，平台另提示折叠 |
| stable_bottom | 问答经复核达到稳定可见底部 |
| manual_confirmation | 根据人工数量确认派生 |
| user_stopped | 用户停止 |
| collection_error | 采集异常 |
| diagnostic_pause | 需人工核对的诊断暂停；具体中文说明另存stop_reason_message，不因诊断文字导致入库失败 |
| NULL | 来源未提供；本轮列表status=limit_reached但此列仍NULL |

stop_reason是最长64字符的ASCII代码列，不是封闭枚举。2026-10-26起，新评价/问答诊断记录使用stop_reason=diagnostic_pause、stop_reason_message保存原诊断；评价导出summary同步保留说明。采集快照生成及写入转换保留符合`[a-z][a-z0-9_]{0,63}`的既有编码及NULL；诊断文本转为diagnostic_pause，并放入result_payload.record.stop_reason_message。旧源记录的stop_reason原文仍保留在result_payload.record和原文件，不改写来源。写入层仅对collection_batches.stop_reason和question_observations.answer_stop_reason提供旧快照兼容，不重写磁盘快照、事件键、指纹及校验值；以后既有的任务补写流程可使用此转换，本轮没有补写真实任务。其他ASCII字段约束继续严格校验。

diagnostic_pause不表示完成，status仍为partial，coverage_status仍按incomplete处理，不能发布有效分区。derivation_kind=manual_confirmation人工确认派生、resume_reuse恢复复用；内部父id与外部原批次键分开。visibility=staging暂存、published可查询、quarantined隔离；published不代表采全或商品上架。

### JSON、版本和搜索来源

- completion_evidence当前人工问答确认为method=manual_confirmation、confirmed_question_count确认题数、confirmed_at确认时间、note人工说明；其他来源证据按原文及版本保留。
- result_payload.record保留去掉items/skus/images/raw_items/raw_html/image_results/unknown_fragments等大明细后的源元数据，原件仍保留。
- scope_contract.version=1含module/scope/mode/requested_limit/answer_limit/filter/sort/keyword/page_number/sort_label；缺失用{"missing":true}，与JSON null分开。
- 显式搜索来源scope_contract.version=2增加search_method/search_image_sha256/search_options；图片内容哈希用于跨库范围身份，不用数据库文件id替代。
- 内部_fingerprint核对快照，_current_sections标记已发布分区，_export_sections选择兼容导出分区，_last_attempt_selected选择最后尝试；公共查询过滤这些控制键。
- _current_sections可以保留该历史批次曾通过发布核对的标记，不会随新批次切换自动清空；确定“当前采用哪批”必须查product_current_sections。第07项中旧批次3的_export_sections从["parameters"]改[]，_current_sections仍保留["parameters"]，业务原文/指纹和旧观察均不变。
- search_options当前关键词为SQL NULL。未来价格、地区、裁剪参数键只有在实现且确认单位/来源后登记，不把示意键当已支持功能。
- schema_version是来源版本。新关键词为3；当前旧历史扫描接受未声明/1/2，不视为支持任意新来源格式。

真实实例：批次2，keyword方式、粘毛器、第1页、销量、上限8、status/coverage_status=limit_reached。collection_mode、stop_reason、search_image_file_id、search_options均NULL，分别按未声明/不适用解释。

### list_observations.ad_status

中文名称：广告识别状态。用途：记录本次列表采集时，是否识别到该商品卡片的广告标记；同商品不同采集批次可有不同结论。

| 取值 | 中文含义 | 何时填写 |
|---|---|---|
| identified | 已识别广告标记 | 命中已适配的标识图片，或识别“广告”文字 |
| not_identified | 未识别到广告标记 | 已执行识别但未命中；不代表确认非广告或自然排名 |
| unconfirmed | 未确认 | 源缺少ad_status键时，转换入库兜底 |

数据库不允许NULL，无默认值，空字符串无正常业务定义。正常页面识别生成前两种；明确传入NULL与缺少字段不同，不会自动兜底。测试夹具曾使用not_detected，属于合成输入原值，不列为当前正常采集状态或真实结果。

payload.ad_label说明标记；ad_basis=specified_image_url表示命中指定标识图；ad_marker_url为图地址。识别广告文字也可identified，此时图片依据可NULL。ad_recommendation布尔值专门表示指定图片标记是否命中，不能替代全部广告结论。

真实例子：观察id=6、batch_id=2、product_id=1，ad_status=identified，ad_label=广告推荐位，ad_basis=specified_image_url；观察id=7、product_id=2为not_identified。本轮3条identified、5条not_identified。

### identity_status、field_states与payload

identity_status=verified表示编号依据已核对，unconfirmed表示未确认/缺字段兜底。payload.link_status为canonicalized_from_list_link（列表直链清理参数）、constructed_from_corroborated_id（交叉依据构造）、constructed_from_dom_id（DOM编号构造）、unconfirmed（未确认）；构造入口不表示打开详情核验。

field_states当前值provided已提供、not_provided源未给、not_identified元素存在但未可靠识别。not_applicable不是本列表当前生成值。当前键包括main_image_url/price_value/currency_symbol/price_label/sales_text/shop_name/shop_url/location_text/rank_title/rank_position/attribute_tags/service_tags/video_url/title_icon_url/customer_service_icon_url/video_icon_url/sku_reference，各键独立判断。

payload分组：

- 身份：平台product_id/product_url、identity_status/link_status/notes；原生product_id则为内部主键。
- 位置与标题：position/slot_index/product_index/title/title_source，title_source当前title_attribute标题属性或visible_text可见文字。
- 价格：price_text/price_value/price_label/currency_symbol/price_integer_text/price_fraction_text；价格标签为页面原文，缺失不可补默认。
- 展示：sales_text/shop_name/shop_url/location_text/rank_title/rank_position/rank_position_text/sku_reference；attribute_tags/service_tags为属性/服务数组。
- 媒体：main_image_url/video_present/video_url/video_icon_url/title_icon_url/customer_service_icon_url；video_present=true可只有标识，视频地址仍NULL。
- 广告与诊断：ad_recommendation/ad_label/ad_status/ad_basis/ad_marker_url、field_states/missing_fields/notes；内部_snapshot_sha核对该规范快照。

真实对应：观察id=6的product_id=1，payload.product_id=996877163053，price_value=16.000000、price_label=首单价；旧观察id=1保留。主图通过相同batch_id、用途与position=slot_index逻辑配对，没有list_observation_id外键。

| 值 | 中文含义 |

2026-10-26起，问大家跳过使运行汇总保持既有complete_with_warnings，warnings记录module=questions、code=questions_entry_not_found及实际说明；原生status/payload/continuation_allowed列已支持实际模块状态和放行依据，无DDL或旧数据回写。统一任务若其他所选步骤均已正常处理，可以succeeded收尾，表示流程已结束，不表示全部数据有效；页面显示含跳过项目，跳过不计入完成数量。

新增日志event_type=collection_module_skipped，INFO级别，details含module=questions、product_id（平台商品编号）、reason=entry_not_found、entry_search（同上），事件归属本次task_id。缺入口本身不再产生manual_wait或needs_attention；登录/验证、错商品、入口不唯一、结构异常及打开后的错误仍执行原守卫。最后一次滚动后会复查入口和明确空态，避免把已出现的入口误判跳过。

Web派发结果增加satisfied（有效结果或有数据库跳过依据时流程已处理）、skipped/reason/message和skipped_count；valid继续仅表示已发布的有效资料，跳过为false且batch_id=NULL。多模块result.modules分别登记每项，satisfied要求每项有效或具有跳过依据；completed_count只统计valid，skipped_count只统计本次入口缺失跳过，skipped_modules仍表示补采计划中因已有有效资料而预先跳过的模块，两者不混用。旧派发没有satisfied时仍按valid判定。

跳过依据从当前task_id+商品关联的最新collection_steps读取，必须是已结束、requested=1、status=skipped、continuation_allowed=1、stop_reason=entry_not_found且entry_search满足10次/3次规则。旧任务、其他商品、旧运行或本地progress不能代替；较新的失败步骤会阻止借用旧跳过。异常退出后的结果恢复同样核对这份证据，不重放采集。跳过不建立全局有效模块，下次新任务仍会寻找入口；本次已有旧有效资料继续保留。

### 新外键与原记录

- search_records.source_list_observation_id → list_observations.id：一条列表观察可以触发多次明确记录的详情入口，每条入口最多一个首次来源；只有record_type=detail_open可有值。外键仅保证目标存在；同任务、同商品、已发布列表及搜索来源一致性由写入程序另外校验。
- collection_runs.entry_record_id → search_records.id：一个入口可以关联多次明确记录的运行，每次运行最多一个入口。写入程序要求入口类型为detail_open、任务和商品一致；外键及索引不是程序归属校验的替代品。
- 两列BIGINT UNSIGNED，可空，无默认值，原生外键更新/删除RESTRICT。同任务重复商品只复用成功详情，后续列表位置的复用关系记录在统一事件和任务汇总，不给同一运行反复改首次来源。
- 新详情批次沿用触发入口的search_method/search_keyword/page_number/search_image_file_id/search_options；写入时对照入口核验。直接输入ID或URL的独立入口没有搜索来源，继续为NULL；来源字段不会改变详情模块scope_key、范围完整性和有效指针的原规则。
- 不把列表批次写成详情模块derived_from_batch_id；该字段仍用于同模块确认派生或恢复复用。

payload.record中的详情入口新增可选entry_key与list_source。entry_key由任务编号、字符串-entry-和12位随机十六进制组成，是入口稳定来源键，不是search_records.id；input_type仍为url或id。列表模式入口JSON文件名使用entry_key，截图名taobao-detail-open-<entry_key>.png，避免多商品覆盖；独立入口保留任务编号文件名。status=opened_pending_dom_review和product_fields_collected=false只表明入口阶段的事实，后续模块完成不会把这份入口原件回写成采集完成。

list_source对象包含source_batch_key（来源列表原批次键，不是内部batch_id）、product_index（该批次从1开始的商品顺序，不是原始格子slot_index）、product_id（平台商品号字符串，不是products.id）。持久快照由这些稳定键在当前库解析source_list_observation_id，禁止把源库内部主键当作跨库身份。详情运行汇总collection_summary保留entry_key及搜索来源，首条collection_steps.payload.run_metadata也保留这些元数据；规范快照的report头含entry_key，page头含list_source。模块快照元数据继承搜索来源，不为此改写旧模块原始文件或旧指纹。

|---|---|

以下只读SQL通过来源外键追溯；不存在的新关联以LEFT JOIN的NULL显示，不能用它推断旧记录已采过列表详情：

```sql
SELECT r.id AS run_id, r.source_run_key, r.product_id,
       e.id AS entry_id, e.source_list_observation_id,
       l.batch_id AS source_list_batch_id, l.product_index,
       b.search_keyword, b.page_number
FROM taobao_automation.collection_runs AS r
LEFT JOIN taobao_automation.search_records AS e ON e.id = r.entry_record_id
LEFT JOIN taobao_automation.list_observations AS l ON l.id = e.source_list_observation_id
LEFT JOIN taobao_automation.collection_batches AS b ON b.id = l.batch_id
ORDER BY r.id;
```

## 2026-10-25 结构化列表销量（0006）

新增list_observations五列，结构版本0006_list_sales；原0001～0005迁移及模型冻结。结构升级先让旧行的sales_count=NULL、precision/metric/period=unknown、parse_status=pending，再由一次性脚本解析原sales_text，只回填五列。pending表示未处理，不能与解析失败混用。解析器版本1，新增采集JSON格式6（与迁移编号分别管理），每个items元素及其list_observations.payload增加五个同名键及sales_parser_version=1；CSV增加对应列。旧原件、payload及原规范快照指纹不重写，历史回填解析规则版本记录在本次报告中。

### list_observations.sales_count

BIGINT UNSIGNED，范围0～18446744073709551615。是展示数值，不是经平台核实的真实成交数。例（格式样例）：1000+人收货→1000；1.2万+人付款→12000；已售500件→500；0人收货→0。万/亿/千按十进制精确计算，不使用浮点数；不能得到整数、超出范围或不支持格式均不存数量。

### list_observations.sales_precision

| 值 | 产生条件与含义 |
|---|---|
| exact | 原文提供无约、无加号、无缩写单位的整数，仅称精确展示，不宣称精确真实销量 |
| lower_bound | 原文明示+或以上，且无约等冲突声明；展示数值为下界 |
| approximate | 原文明示约，或万/亿/千缩写但未明示下界；不制造误差区间 |
| unknown | 没有可靠数值；sales_count必须为NULL |

### list_observations.sales_metric

paid_people仅匹配人付款/人已付款；received_people仅匹配人收货/人已收货；sold_units匹配件/件已售；unknown表示没有明确支持的口径，不把人数当件数。不同口径不能直接合计。

### list_observations.sales_period

cumulative仅原文明示累计；monthly来自本月/月售/月销；last_30_days来自近30天/近30日/最近30天；unknown表示未声明、冲突或无法识别，不默认累计。monthly与last_30_days不能混用，不补造周期起止日期。

### list_observations.sales_parse_status

| 值 | 产生条件 |
|---|---|
| parsed | 支持的完整格式且数值为有效非负整数；count非NULL，precision不是unknown |
| no_quantity | 非空原文无数字，例如本月行业热销；明确周期仍可保留 |
| unrecognized | 含数字但不符合支持格式、多个数值/口径、精度声明冲突或溢出，例如行业热销前10 |
| not_provided | NULL、空或纯空白文本；count为NULL，不是0 |
| pending | 升级旧行的初始值或外部未解析数据；新采集保存前完成解析，不正常生成pending |

数据库检查约束限定四组代码，以及parsed必须有数量和有效精度、其他状态必须数量NULL且精度unknown；保留原文是兼容和核对依据。ix_list_sales_count(sales_count,id)辅助数量查询，不改变主外键或去重规则。

旧规范快照缺少五列时，写入层从原文初始化；原文相同且已有非pending结果时保留已有五列，不能用旧缺失值清空回填结果。只允许pending行初始化这五列，不放宽其他不可变字段冲突检查。已有快照若显式携带部分新字段则拒绝，防止混合版本造成矛盾。

网页参数sales_min/sales_max为非负整数，允许单边、包含边界；存储查询接口的sales_metric/sales_period/sales_precision按上述白名单；当前网页仅提供最小值～最大值区间，不展示这三个下拉筛选，旧网页链接中的这三个条件自动清除。区间留空表示不限，不默认0，明确输入0才表示零。sort=sales时按sales_count排序，空值无论升降均末尾，记录编号稳定兜底，先全量筛选排序再按20条分页。商品汇总先选范围内最新观察，再筛销量；历史模式各条独立。网页明确“按展示数量筛选”：1000+按1000参与，不表示实际销量低于筛选上限。模糊数量不能当精确合计，不同口径/周期不能混加，跨次观察不能直接累加或相减成真实新增销量。

本次真实回填例（2026-10-25）：list_observations.id=2，batch_id=1，原文1万+人收货，sales_count=10000、sales_precision=lower_bound、sales_metric=received_people、sales_period=unknown、sales_parse_status=parsed。无法识别例id=17，原文行业销量前10，count=NULL且parse_status=unrecognized。完整前后证据见[实施记录](变更记录/列表销量结构化实施记录.md)。
