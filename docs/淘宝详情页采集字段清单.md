# 淘宝详情页逐步采集清单

用户要求：先打开单个商品详情页，按其逐批指定的区域接入采集；同一方法后续供独立入口和列表循环复用。

## 第一步：主图画廊的视频

测试商品 ID：`1050158363561`。用户截图圈出的区域是左侧首个主图缩略图，对应右侧主图视频播放器。用户明确选择下载视频文件，同时保留原链接。

| 项目 | 规则 |
|---|---|
| 检测范围 | 唯一主图画廊 `#picGalleryEle`，不扫描推荐、评价等区域的视频 |
| 视频节点 | `#picGalleryEle #mainPicVideoEl video`；同一区域 `[class*="mainPicVideo--"] video` 兼容定位 |
| 首个槽位 | 已选中则复用；其他图片被选中时只点击首个缩略图一次，确认选中后读取 |
| 资源地址 | 实际播放器 `currentSrc`，其次 `src`、子节点 `<source src>`；原样记录，不拼接或猜测媒体地址 |
| 有视频 | 下载当前支持的普通 MP4 直链，同时记录原链接、时长、路径、字节数和 SHA-256 |
| 无视频 | 画廊、首个缩略图和主媒体加载已确认，复核无视频节点/标识，返回“无视频”并跳过下载 |
| 尚未加载或结构未知 | 暂停人工处理，不当作无视频 |
| 有视频但地址不可下载 | 明确记录 `unsupported_source` 或 `download_failed`，不当作无视频，不自动重试 |
| 文件检查 | 单次流式下载，检查响应类型、MP4 文件头和完整长度；停止/异常清理本次 `.part` |
| 人工处理 | 沿用现有验证守卫，收到明确“继续”且页面复核通过后恢复 |

调用方式：

```powershell
.\.venv\Scripts\python.exe main.py taobao detail --input "1050158363561" --video
```

入口层 `modules/collection/detail_service.py` 调用 `modules/collection/detail_video.py` 的 `collect_main_video`；DOM 检测位于 `platforms/taobao/detail_video.py`。下载完成后默认保留详情页，等待下一批字段。其他详情字段和循环采集尚未接入。

用户后续确认资料按商品 ID 整理。最新资料在 `workspace/output/raw/taobao_details/<商品ID>/`：视频为 `<商品ID>.mp4`（当前支持的原视频格式为 MP4），统一详情文件为 `<商品ID>.json`，视频数据存入 `video` 分区，后续采集其他分区时合并更新，保留已有字段。JSON 同时保存相对文件名 `video_file` 和本地路径。

每批原件在 `history/<批次编号>/` 保留 `<商品ID>.mp4` 与 `video.json`，商品目录发布最新视频及统一 JSON。无视频只保存 JSON，`video_present=false`、`video_status=no_video`、`skipped=true`，旧视频原件保留在历史目录，最新目录不沿用旧视频。原媒体链接可能包含时效签名，按用户要求保留在本地输出，日志不输出签名参数。

后续建议将主图、详情图分别存到该商品文件夹的子目录，文件扩展名保持真实格式；按用户逐批确认后实施。当前已实现视频命名、统一 JSON 分区合并、历史保留及更新失败恢复原视频。

## 第二步：按实际数量采集主图

主图按页面实际图集数量全部采集，不固定要求五张，也不以五张截断；原核对样例为五张。排除视频封面及参数入口，保存到 `taobao_details/<商品ID>/1-1主图/`。按页面图集顺序从 1 编号，保留真实格式扩展名，不转换或裁剪图片。

实测页面结构为：唯一 `#picGalleryEle`；`thumbnails--` 下七个 `thumbnail--` 槽位中，位置1为视频封面，位置2～6为五张主图，位置7为“参数”。“视频”切换入口用于识别首个视频槽位；无视频入口的商品从首张图片开始，不固定跳过第一个位置。

当前实现直接读取 `window.__ICE_APP_CONTEXT__.loaderData.home.data.res.item.images`；缺失时使用已核对的 `res.componentsVO.headImageVO.images`，两者同时存在须均与图集的图片来源、数量及顺序对应。数据内 `item.itemId` 必须匹配目标，若提供 `ssrItemId` 也须一致。下载与发布前复核本批清单；变更则等待人工明确反馈。只读取上述已适配字段，不搜索推荐区图片，不调用额外商品接口，不点击或悬停缩略图，不依赖当前大图选中项；“参数”面板已打开也可读取主图列表。缩略图提供地址即可，不依赖缩略图字节加载完成。不通过改写或去参数构造下载链接。相同来源在不同图集位置仍保留相应编号。

JSON `main_images` 分区记录动态的 `expected_count`（本批确认的实际主图数）、`available_count`、`collected_count`、状态及有序 `images`；每张含 `index`、原始槽位、缩略图链接、页面数据提供的图片链接、相对文件名、路径、真实格式、尺寸、大小及 SHA-256。`collection_method=page_data`、`source_path` 和 `verified_source_paths` 标明数据来源。原文件串行下载并由浏览器原生解码验证，沿用 `page` 间隔；实际格式可能为JPG/PNG/WebP，不转换图片。成功后发布到商品目录；历史文件及 `main_images.json` 保留在 `history/<批次编号>/`。

下载前及每张完成后保存 `main_images.json` 和 `main_images_last_attempt`；后者不覆盖已有完整 `main_images`。`image_results` 包含全部序号及 `pending/downloading/downloaded/reused/failed/interrupted` 状态，批次状态为 `in_progress/complete/download_failed/interrupted`。再次运行原命令时，只有上次未完成批次的商品ID、完整有序来源及位置一致，且原文件格式、大小和SHA-256都通过复核，才复制成功项到新批次并补采剩余项；损坏文件重新下载。若补采再次中断，沿 `resumed_from_batch_id` 已登记关系复核更早同来源未完成批次，不扫描无关历史；每张 `reused_from_batch_id` 记录实际原件来源。记录 `manifest_fingerprint`、`resumed_from_batch_id`、`reused_count` 和 `downloaded_count`；旧版和完整批次不自动复用，原件保留。任一失败停止本次后续下载；只有全部成功才发布最新文件夹和完整分区。

入口为 `taobao detail --input "1050158363561" --main-images`，可和 `--video` 同时使用，顺序执行视频和主图。页面数据及DOM适配在 `platforms/taobao/detail_images.py`，下载、进度恢复与发布在 `modules/collection/detail_images.py`；复用现有守卫、任务锁和统一 JSON 分区合并，保留视频资料。页面1张、3张或多于5张均按实际数量采集，全部保存才标记 `complete`；空白、数据缺失、图集变更及未知入口仍复核。下载失败记录失败批次，不将未完成的图片集发布为成功。下方历史五张验收记录属于旧版逐张点击流程，保留原样。

- 多规格商品使用完整规格组合名称；多个 SKU 共用一张图片时，仍分别按各自名称保存。确认无货的 SKU 有对应图片时也照常保存。

### 字段、识别与操作顺序

- 商品基础信息：完整标题、售出件数原文及数值口径、评价提示、回头客提示、加购提示和采集时间。`已售 10万+` 保留原文，只另记下限100000，不当作精确销量或月销量；`312人评价“有价值”` 为原文提示，不当作总评价数。
- SKU 区域限定为唯一可见 `#skuOptionsArea`，按 `skuItem--` 识别规格组、按 `valueItem--` 识别选项，排除隐藏副本和区域外推荐。动态读取数量，保留 `data-vid` 为规格值标识，不将其当作 SKU ID；仅页面明确提供有效正整数 `data-sku-id/data-skuid` 且组合已确认时记录 SKU ID。`sku_identity_status` 区分 `explicit_dom_id/not_provided`；名称包含服务说明、负数规格值标识、禁用选项均不自动过滤。尚未适配页面结构化SKU映射，不猜测真实SKU总数。
- 单组规格逐项选择；多组规格枚举完整组合，解除旧选择后按组选择，重新读取联动的禁用与缺货状态。只读到灰色/禁用不直接推断缺货，未能确认的候选组合单独标注，不以理论组合数充当实际已确认数。规格结构改变、未知或尚未加载时暂停，不返回0个SKU。
- 购买数量必须为1；数量不符时等待人工修正。每项通过 Playwright 单次点击，确认各组实际选中状态；价格无加载标记、相关请求结束、DOM稳定且满足最短等待后读取。相邻 SKU 同价可正常记录，不要求价格必须变化；操作失败不自动重放。
- 可售 SKU 记录展示价格、十进制金额字符串 `price_value`、币种、价格标签、同一区域展示的价格明细及 `price_checked_at`；保留“优惠前”等原标签，不改称到手价。明确无货使用用户指定文案，数值字段为空；禁用原因未明则价格为空，`price_reason` 标注原因、`unavailability_evidence` 保留禁用属性/类名，结果为部分完成。可选价格未确认或请求失败仍暂停人工复核，不沿用上一规格的价格。
- SKU 图片优先采用页面明确提供的大图地址，或与该选项图片核对为同资源的当前主图；否则使用该选项实际提供的图片并标注来源。绝不通过删除尺寸参数猜测地址。多规格保存完整组合名称，有图片的无货 SKU 也下载。

### 保存、完整性及复用

统一 `<商品ID>.json` 新增 `product_info` 和 `sku_details` 分区，完整批次一次合并发布，保留已有 `video/main_images`。`summary` 分别统计 `option_count/candidate_count/processed_count/recognized_count/selectable_count/explicit_sku_id_count/sku_id_unconfirmed_count`，以及价格、缺货、不可选和图片成功/复用/失败/缺失数量，不把候选数量当实际SKU总数。`warnings` 含异常选项名称及原因，`blocking_issues` 含组合、价格或图片的阻断项。

每批原记录及原图保存于 `history/<批次编号>/sku_details.json` 和 `history/<批次编号>/sku图/`。每项价格及每张图片开始/完成均保存 `sku_progress.json`，与商品 `sku_details_last_attempt` 一起保存阶段、状态和已处理数；中途中断标记 `interrupted`，正常结束后也保留该进度文件。本轮价格全部重新确认（`price_refresh_policy=always_current_run`），不将上次价格写入新批次。仅同商品、相同规格清单及完整组合、相同SKU标识和实际图片地址，原件的格式、大小、SHA-256验证通过后复用图片到新批次；记录 `inventory_fingerprint`、`resumed_from_batch_id` 和每图 `reused_from_batch_id`。可沿恢复关系查找更早未完成批次，兼容已登记的旧版部分图片；不复用已完整批次、不修改历史原件。
