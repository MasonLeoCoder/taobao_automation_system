在数据库客户端可复制以下只读SQL，直接核对某来源词：

```sql
SELECT id, task_id, search_method, search_keyword, page_number,
       search_image_file_id, search_options, sort_label, captured_at
FROM taobao_automation.collection_batches
WHERE search_method = 'keyword' AND search_keyword = '粘毛器'
ORDER BY captured_at DESC, id DESC;
```

SQL中的keyword为搜索方式代码，粘毛器为实际来源词；替换来源词即可查看其他关键词。历史未记录的页码或条件保持NULL，NULL不表示零或确认没有条件。升级记录和本轮字段前后值见[搜索来源升级报告](../变更记录/搜索来源字段升级验收报告.md)。

## 淘宝第一页商品采集（PowerShell）

先关闭上一次保留的测试浏览器并等待任务退出，然后执行：

```powershell

程序沿用淘宝独立登录资料，从首页提交一次搜索，随后自动点击“销量”，确认该页签已选中且商品列表更新，再读取第一页已经加载的商品卡片。保存后显示件数和两个文件的完整路径。默认保留窗口供核对，关闭搜索标签页结束任务；需要保存后自动关闭，在命令末尾加 `--no-wait`。

正式流程为：**复用登录 → 输入关键词并搜索一次 → 等待列表加载 → 点击销量一次 → 核对排序和列表更新 → 同页分段加载主图 → 逐格分类并采集 → 保存 JSON/CSV → 保留浏览器**。默认按销量，无需增加命令参数；`taobao search` 仍只搜索并保存摘要，不执行采集排序步骤。

排序按钮已经选中“销量”时直接复核复用，不再次点击。网址不一定变化，因此同时读取真实排序页签的选中状态；点击后检查商品内容变化、列表重新建立或页面导航等更新证据，并等待加载提示消失。排序前、结果确认后分别复用 `before_search`、`search` 的间隔配置，默认均为 2～4 秒。

排序入口缺失、重复、不可用，或点击后未能确认排序/列表更新时，记录现场并暂停，请人工处理后输入 `继续`。不会自动再次点击销量、重新搜索或按综合排序继续采集。明确无结果的页面保存空批次，无商品可供排序。

默认--page为1，不限制每页条数，采集第一页已加载的全部有效商品。只有显式添加 `--limit 正整数` 时才限制最多保存的有效商品数量，例如 `--limit 20`；没有固定 50 件上限，0、负数和非整数会在启动浏览器前报错。--page正整数指定从第一页起最多采几页；--limit为每页上限。例如`python main.py taobao collect --keyword "粘毛器" --page 3 --limit 3`最多保存三页各三条。每页独立JSON/CSV及数据库批次，下一页之前确认当前页已保存并入库；明确末页可提前结束。

首屏外主图可能延迟加载，程序会在同一页分段滚动并按 `scroll` 间隔等待，确认显示主图节点出现后再读取；同页加载图片期间不翻页、不打开详情；当前页保存后按--page继续下一页。滚动和短等待均有上限，仍未取得的字段明确标记；指定上限但商品不足时按实保存，不承诺采满。

| 保存内容 | 说明 |
|---|---|
| 商品ID、完整标题、主图、商品链接 | 从列表内单个格子读取；标题优先用完整 `title` 属性，主图只取显示主图区 |
| 店铺、店铺链接、页面地区 | 店铺链接保留公开路由必要参数，去掉跟踪参数，缺失时标明原因 |
| 展示价格、价格数值、价格说明 | 保留“首单价、补贴后、优惠后”等条件；不是最终结算价；无法识别单一数值时保留原文 |
| 销量提示原文 | 保留“4万+人付款”“1万+人收货”等文字，也可能是“本月行业热销”等提示；不转换成精确销量或月销量 |
| 商品 ID、商品链接 | 详情直链去除跟踪参数；推广链接 ID 交叉核对后才采信，生成的普通入口会标明未打开验证；不能确认时留空 |
| 关键词、实际页码、展示位置、时间、批次、排序 | 有商品时必须确认“销量”，排序不明则暂停；明确空结果时允许无排序，另作标记 |
| 广告标记、字段缺失、备注 | “未识别广告标记”不代表非广告，不据此判断自然排名 |
| 榜单名称/名次、属性标签、优惠服务标签 | 保留原文；榜单名次不作为搜索位置 |
| 视频标识、视频链接、图标链接 | 图标与视频文件分别保存；有播放图标但无视频地址时记为页面未提供 |
| 原始格子位置、连续商品序号 | 跳过调查卡后仍能对应原页面位置，同ID不同展示位分别保留 |

用户已确认两份 DOM 字段清单，新版从 `#content_items_wrapper` 的直接子格子读取。广告图片命中时 CSV 的“广告推荐位”显示“是”，“广告识别依据”记录命中原因；图片 URL 和选择器见 [单商品 DOM 字段清单](../采集规范/淘宝列表页商品卡DOM字段清单.md)。未命中该图显示“未检测到指定标记”，不推断为自然排名。

每次任务的每页分别生成新批次，使用相同task_id、不同batch_id和实际page_number，保留历史。同一商品在不同展示位分别保留；已确认调查卡，以及同时具有 `suggestItemCard--` 结构和“大家都在搜”标题、且没有商品入口的推荐词卡，单独统计并跳过，不占商品数量。不点击调查评分或推荐词。采集范围内未知内容、商品 ID 冲突或缺少标题/展示价格时暂停，不静默略过。只有页面明确显示无结果，才保存空结果。

CSV 的“字段状态说明”区分页面未提供、元素或内容未识别、不适用，缺失值不填成 0。JSON `counts` 记录全页已加载格子的分类数量及本批导出数量，其中 `search_suggestions_count` 为推荐词卡数量；广告和破损商品作为商品子集统计，不重复加进格子总数。未传上限时 `requested_limit=null`，正常采完当前页记为 `all_loaded_cards_collected`；显式限制时，上限之后的未知格子记录在 `issues` 中，范围内的未知项仍会暂停。

CSV 的“采集时间”统一转换为北京时间，格式为 `YYYY-MM-DD HH:mm:ss`，例如 `2026-10-21 13:14:02`；同一批页面快照的商品共用采集时间。JSON 保留原始带时区的 ISO 时间，例如 `2026-10-21T05:14:02+00:00`。此规则适用于新导出的 CSV，已有历史文件保留原样。

JSON 中 `requested_sort="sales"`、`sort_label="销量"`、`sort_status="confirmed"` 表示已确认平台销量排序；空结果无需排序时记为 `not_applicable_empty_results`。平台展示的销量排序不保证每条提示都可比较为精确数字，也不排除广告，因此不在本地猜测销量数值后重新排列。

- 最新详情资料集中在 `workspace/output/raw/taobao_details/<商品ID>/`：视频为 `<商品ID>.mp4`，统一详情 JSON 为 `<商品ID>.json`。视频结果保存在 JSON 的 `video` 分区，含有无视频、状态、原链接、相对文件名 `video_file`、本地路径、字节数、SHA-256、页面提供的时长和采集时间；后续其他资料分区合并到同一 JSON，保留已有字段。
- `history/<批次编号>/` 保留每次的原视频和 `video.json`，重复采集只更新商品目录中的最新资料，历史批次保留。无视频时保存 JSON 并跳过视频文件；若之前存在视频，其历史原件仍保留，最新目录不沿用旧视频。
- 只指定 `--video` 时，仅采集视频，完成后默认保留详情页；`--no-wait` 则关闭窗口。组合启用其他步骤时继续执行这些步骤，不进入其他商品。

规则如下：

- 纯数字 ID：去掉两端空格后，拼接 `https://item.taobao.com/item.htm?id=` 加原 ID。须为 1～25 位正整数。
- 详情链接：支持 `http/https` 的 `item.taobao.com/item.htm` 和 `detail.tmall.com/item.htm`，须有唯一有效 `id`。打开时保留输入链接的规格和其他查询参数；入口记录仅保存去跟踪参数的商品地址。
- 沿用淘宝独立浏览器资料和登录状态，与搜索采集共用串行任务锁；先结束上次保留的测试任务后再运行。单次导航使用 `page` 间隔，默认 4～8 秒；验证或异常暂停待人工，不自动重开或刷新。
- 保存入口 JSON 到 `workspace/output/raw/taobao_detail_open/<任务编号>.json`，截图到 `workspace/logs/screenshots/taobao-detail-open-<任务编号>.png`，然后执行已选采集步骤；默认完成后保留窗口，加 `--no-wait` 则所选步骤正常完成后关闭。
- 关闭详情标签页可结束任务；验证后的 `继续` 和 `taobao continue`、`pause`、`stop`、`confirm`、`cancel` 沿用现有机制。

底层 `platforms/taobao/detail.py` 的 `open_detail(page, input, timeout_ms)` 接受调用方提供的页面；列表循环复用此方法及`detail_service.collect_detail_page`，保持同一浏览器会话。独立入口在 `modules/collection/detail_service.py`；各步骤选择器按已核对的单商品 DOM 接入，未知结构暂停人工复核。

```

主图保存在商品目录的 `1-1主图` 子文件夹，按图集显示顺序从 1 编号，扩展名与实际图片格式一致。例如页面3张则保存 `1.webp`～`3.webp`，页面8张则保存全部8张。只运行 `--main-images` 时合并已有商品 JSON，保留视频分区。

直接下载DOM提供的地址，保留`_q50.jpg_.webp`等后缀和查询参数，`//`地址按页面协议补全；去重忽略URL片段，保留不同路径、查询和压缩版本的区别。图片不裁剪、不重新编码，不推导原图。文件按`1.webp、2.webp…`等顺序命名，扩展名以实际响应格式为准。下载串行执行，沿用 `[taobao.pacing].page` 间隔（默认4～8秒）；文件头、完整长度、浏览器实际解码及SHA-256均检查。

新主图记录为`schema_version=3`、`collection_method=dom_thumbnails`，保存去重后顺序、首次出现的缩略图位置、图片及缩略图链接、文件名、尺寸、字节数和校验值，以及DOM来源`source_path`/`verified_source_paths`。`raw_image_count`为原始图片节点数，`duplicate_count`为去除数量，`deduplication=normalized_url_first`。`expected_count`和`available_count`为去重后数量，`collected_count`为成功保存数量；例如6节点去重为5张，则前两项为5，全部保存后collected_count为5、status为complete。空列表不当成0张成功。旧`schema_version=2`/`collection_method=page_data`批次按历史规则保留。

全部图片成功才整批更新最新主图文件夹和 `main_images`。重复完整采集更新最新资料，数量减少时移除最新目录中的旧尾部文件，原批次仍保留；发布失败恢复旧主图和完整JSON分区，未完成批次不标记成功。

完成后默认保留详情页；其他采集项可通过上方参数表组合启用。

### 采集标题、售出件数、SKU价格和图片

```powershell
.\.venv\Scripts\python.exe main.py taobao detail --input "1050158363561" --skus

```

程序动态识别商品规格组与选项数量，逐项选择 SKU；多组规格按完整组合选择并核对联动状态。购买数量须为1，其他数量提示人工修正。确认选中状态、价格加载和相关请求结束并稳定后读取，不要求相邻 SKU 的价格不同，不自动重试点击。当前只适配已核对的 `#skuOptionsArea` 规格区域；缺少区域、选项身份变化或价格不明时暂停人工核对，不当作无SKU或无货。

图片保存到 `workspace/output/raw/taobao_details/<商品ID>/sku图/<SKU名称>.<真实格式>`，多规格名称包含完整属性组合。SKU共用图片时仍各存一份；无货SKU有图片也保存。优先使用页面提供的大图或与SKU图片匹配的当前主图，否则保存该选项实际提供的图片并记录来源，不拼接大图链接。名称中的Windows非法字符作必要替换，保留JSON原名称；重名增加唯一后缀。未显示图片与下载失败分别标记。

商品JSON新增 `product_info`（标题、售出件数原文及数值口径、评价/回头客/加购提示、时间）和 `sku_details`（规格组、SKU名称、规格值标识、页面明确提供的SKU ID、价格、币种、价格标签、状态、图片链接/路径/尺寸/哈希及完整性统计）。`option_count`为规格选项总数，`candidate_count`为候选组合数，`recognized_count`为组合已确认数；`explicit_sku_id_count`另记页面明确给出的正整数SKU编号数量，缺少编号时 `sku_id=null`、`sku_identity_status=not_provided`。不把选项或理论组合数称为真实SKU总数，不按名称、负数 `data-vid` 或禁用状态删除选项。金额数值以十进制字符串记录以保留精度。`已售10万+`只记录销量下限，不当作精确销量或月销量；“优惠前”按原标签记录，不当作券后价。

明确无货的SKU价格默认填写 **“当前缺货，无法识别价格”**，`price_value=null`；仅禁用而无明确缺货依据的标记为原因未确认，价格留空。`price_reason`记录具体原因，`unavailability_evidence`记录禁用属性/类名，`price_checked_at`记录本轮核对时间。该选项的名称、原图片和候选组合均保留；日志逐项显示异常名称及原因，不仅输出19/20这样的数量。汇总含候选/已确认数量、显式SKU编号数、价格成功数、缺货数、不可选原因未确认数、图片成功/复用/失败/无图片数。

每批原件在 `history/<批次编号>/sku图/` 和 `sku_details.json`。每项价格核对后、每张图片下载前后保存 `sku_progress.json` 及商品JSON的 `sku_details_last_attempt`，记录 `phase`、状态、已处理数、警告和阻断原因；正常结束后也保留进度记录，中途停止标记 `interrupted`。

重新运行原命令时，**本轮所有价格重新确认，不复用旧价格**（`price_refresh_policy=always_current_run`）；仅对已登记的同商品未完成批次，规格组、选项名称/顺序/标识一致，且组合、SKU标识、图片地址一致的原图，校验真实格式、长度和SHA-256后复制到新批次复用。损坏、来源或规格改变的图片重新下载；完整旧批次不自动当缓存。补采再次中断时沿已登记的恢复关系查找原件，不扫描无关历史。旧版部分结果具备完整图片登记时也可复用其图片，原件保持不变。

完整批次原子发布商品目录最新 `sku图/`、`product_info` 和 `sku_details`；部分批次保存在 `sku_details_last_attempt` 与本次历史目录，不覆盖此前完整结果。日志及 `collection_summary` 会给出本次部分JSON与图片目录，即使后续模块已继续，SKU本批也保持部分完成。保存失败恢复原完整分区和图片。完成后默认保留页面供检查，加 `--no-wait` 结束所选步骤后关闭。

### 动态采集参数信息

```powershell
.\.venv\Scripts\python.exe main.py taobao detail --input "1050158363561" --parameters
# 在同一次详情流程中依次采集视频、主图、SKU和参数
.\.venv\Scripts\python.exe main.py taobao detail --input "1050158363561" --video --main-images --skus --parameters
```

程序定位当前商品的唯一 `.paramsInfoArea`，动态遍历突出参数和普通参数，不预设类目名称或条数。突出参数的值在上、名称在下，普通参数按名称和值读取；优先读取节点 `title` 完整原文，否则读取显示文字。单位、多值、换行和相同参数名保留，按DOM顺序存成列表。参数模块不存在但有唯一“参数信息”页签时只点击一次定位；模块已存在则滚动至可见区域。明确的展开入口按当前DOM定位点击，等待加载稳定，同一入口不会自动重放。

商品JSON新增 `parameters` 分区，包含 `items`（顺序、名称、原始名称、参数原值、突出/普通来源、取值来源和读取状态）、`summary`、本批状态及HTML路径。`total_count` 是已识别的参数条目数，只有 `total_count_confirmed=true` 时才表示已确认模块完整数量；同时记录成功读取数、空值数、异常数和未解析片段数。空值保留并标注 `empty_value`；缺少值节点属于异常。页面明确显示“暂无参数信息”等才记录 `no_parameters`，未加载或未知结构不算0个参数。

每批保存 `workspace/output/raw/taobao_details/<商品ID>/history/<批次编号>/parameters.json` 和原始模块 `parameters.html`，HTML按UTF-8原样保存，记录字节数与SHA-256。参数模块内尚未解析的文字、媒体或标题属性会触发人工复核；保存本次诊断JSON及可获取的HTML后暂停，收到“继续”再检查。诊断资料命名 `parameters-attempt-<序号>.json/.html`，并更新 `parameters_last_attempt`，保留此前完整参数。发布前复核参数快照，发生变化时等待人工确认后重新读取。

完整结果合并进同一商品JSON，保留视频、主图和SKU分区；保存失败不覆盖原JSON，历史保留。本步骤结束后保持页面，`--no-wait` 则结束所选步骤后关闭。当前适配上述已核对结构，其他布局需复核适配；独立详情命令只处理输入商品；列表循环由`taobao collect --with-details`启用。

### 采集逐条用户评价

```powershell
# 默认最多保存100条有效评价
.\.venv\Scripts\python.exe main.py taobao detail --input "1050158363561" --reviews
# 取消数量上限，采集到页面明确的评价列表末尾
.\.venv\Scripts\python.exe main.py taobao detail --input "1050158363561" --reviews --all
# 同时更新评价概览和逐条明细
.\.venv\Scripts\python.exe main.py taobao detail --input "1050158363561" --review-summary --reviews
```

`--all` 取消所选评价和问题的数量上限；默认全功能模式下同时取消两者上限。显式指定功能时，必须包含 `--reviews` 或 `--questions` 才能使用 `--all`，例如 `--skus --all` 会在启动浏览器前报错。单独的 `--review-summary` 仍只采概览。逐条采集可与视频、主图、SKU、参数、详情图组合，在这些步骤和概览之后运行。无功能参数时默认执行全部详情采集步骤。

程序单次点击“查看全部评价”，限定当前商品的评价侧栏，确认“全部”筛选并记录默认排序；保留该筛选和排序。先读取当前已加载评价、逐批事务保存，再用Playwright在评价列表内滚动约65%可视高度。等待加载完成和内容稳定后读取下一批，兼容旧节点被回收的列表，不滚动整个商品页面来代替侧栏滚动。

每条保存用户显示名称、评价日期原文及可解析日期、SKU、完整正文、图片链接、视频链接、追评及追评时间原文、采集时间。已核对的懒加载占位图不作为评价图片地址；待对应图片进入可视区域、真实链接出现后才保存该条，维持页面顺序。媒体地址变化只更新同一记录，不增加计数。媒体只记录实际DOM链接，不下载、不拼接高清地址。视频在列表只显示封面时，单次打开对应买家播放器，核对用户、日期、SKU、正文归属，从BlackLightPage内itemVideo读取实际地址，随后单次关闭回到列表；不取商品主图播放器地址。视频封面另存video_poster_urls，同条视频使用缓存避免重复打开；播放器地址未就绪或归属不符时等待人工复核。商家回复、头像、信用图标不进入评价明细。全文展开入口单次点击，仍未完成时交给人工，不能重复点击碰运气。

追评同时兼容独立区域和嵌套在初评正文容器中的布局。初评读取时排除追评节点；每段追评分别保存正文、时间原文及媒体链接，保持顺序，不把追评媒体混入初评。正文内的“32天后追评：”等已确认时间标签单独保存为 `time_raw`，追评正文不重复包含该标签。系统默认初评附有真实追评时保留完整记录，未知追加内容仍暂停检查。

商家回复无论在评价卡片外层、初评容器内还是追评内，都从采集范围排除：不保存回复正文和媒体，不点击其中的“更多”或全文按钮，也不因商家回复自己的加载状态而等待。识别使用已确认的商家回复区域；通用 `reply--` 区域还须带明确“商家回复：”或“店家回复：”标识。买家正文中引用“商家回复”的文字仍保留；未知买家内容仍暂停，不会因旁边有商家回复而整段忽略。

结构或业务结果未通过检查时，终端显示“需要人工检查”；滑块等安全验证仍显示“需要人工验证”。两者都必须明确反馈并复核，不会自动放行。代码修复不会自动更新已经运行的任务：旧任务在提示处输入 `停止` 并退出后再运行修复版本。若完整采集停在评价步骤，可仅重跑剩余两项：

```powershell
.\.venv\Scripts\python.exe main.py taobao detail --input "972088879573" --reviews --questions
```

上述命令以新批次重新读取评价，然后采集问大家，不会重新下载视频、主图或详情图。以前已保存的部分评价保留在原历史批次；当前不支持跨任务从第41条自动接着采集。

仅含“该用户觉得商品非常好，给出好评”的评价按去除空白后的全文精确匹配过滤，不占100条名额。附有真实追评或买家媒体时保留有效记录；纯图片评价也保留。其他模板不自动扩大过滤范围。统计区分已检查记录数、有效采集数、模板跳过数；追评及图片视频不单独计数。一批超过100条时按页面顺序保留前100条有效记录。

优先使用页面评价ID去重。没有ID时使用用户、日期规格、正文、追评文字及同批相同记录出现序号（可变媒体链接不参与身份），保留同一批内完全相同的多条节点，并标记 `identity_exact=false`。不同用户的相同文字保留；页面没有稳定ID时，无法保证区分跨窗口完全相同的匿名记录，JSON保留身份识别方式说明。

结果位于 `workspace/output/raw/taobao_details/<商品ID>/用户评价/评价明细.json` 和 `评价明细.csv`；CSV使用UTF-8 BOM和北京时间 `YYYY-MM-DD HH:mm:ss`，JSON保留原始ISO时间及原文。CSV中可能被表格软件当成公式的文字加文本前缀，原文在JSON中保持不变。商品总JSON的 `reviews` 保存统计、筛选排序、结束原因、文件路径、长度及SHA-256，明细不重复塞进总JSON。明细JSON另有 `summary`，保存本批条数、结束原因、标题数量原文与口径、平台折叠数量和完成证据；CSV仍仅列评价，不混入汇总行。

结束原因分别为：`limit_reached` 达到100条有效记录；`end_of_list` 页面明确到达末尾；`folded_visible_end` 平台折叠提示所在的可见列表底部已多轮复核；`no_reviews` 已确认无评价。达到100条不表示全部采齐。列表不足100条时，按明确末尾或下方折叠末尾规则正常完成。无评价必须有明确空态，或已确认的概览数量为0且没有评价入口；日志显示“商品 <商品ID>：无评价”，JSON的status为no_reviews、message为无评价、collected_count为0。评价全部被模板过滤时，仍是有评价但没有有效记录，不标记无评价。

“已折叠……条对你帮助不大的评价”本身不代表结束。只有该提示位于最后一条已加载评价之后、没有展开/加载入口或未知尾部控件、滚动区确实到底、所有已加载评价及媒体已处理完，并且连续3轮滚动等待后内容、位置和高度都不变，才按 `folded_visible_end` 完成。每轮折叠底部复核最多等待5秒，并保留正常滚动间隔；出现加载状态时仍使用配置的完整加载等待预算。底部新增评价或内容变化会重置轮数。

该完成范围仅为“当前页面可见评价”，不承诺取得平台未展示的折叠记录。`collected_count`记实际有效条数，`folded_count`单独记平台折叠数，`folded_text`保留提示原文，`review_count_display`保留“2000+”等标题原文及数值口径，`bottom_confirmation_rounds`及`completion_evidence`保留判定证据；不把折叠数加进已采条数。例如页面显示2000+、实际可采53条、折叠1978条，结果记录53和1978，不报告采齐2000多条。

没有明确末尾且不满足上述全部折叠条件时，连续3轮无新增仍保存当前明细并暂停核对。尚未到底、图片未加载、未知按钮、页面仍在加载等情况不会因折叠提示而放行。每500次滚动设人工核对点，继续后保留累计进度，不截断条数。验证码、异常弹窗、未知结构、商品或筛选变更沿用守卫，等待人工明确继续并复核；不自动刷新、切换账号或重放失败动作。

每批保留 `history/<批次编号>/reviews-progress.sqlite3`（逐批事务记录）、`reviews-progress.json`（统计进度）、`用户评价/`（导出的JSON/CSV）及 `reviews.json`（批次记录）。完整批次先校验副本，再整体发布两份明细和总JSON；发布失败恢复原文件夹。被手动修改或含未登记文件的现有目录不覆盖。暂停/停止的明细与统计写入历史和 `reviews_last_attempt`，保留此前正式结果。正常完成清理进度JSON，历史数据库保留；当前不自动跨任务续采。默认保留详情页，`--no-wait` 完成后关闭。

### 采集问大家

入口寻找采用10次滚动上限：每次向下约四分之三屏后重新检查，连续3次页面位置和高度不变时提前停止；最后一次滚动后仍会复查，避免漏掉刚出现的入口。仍找不到“查看全部问答”时返回`skipped / entry_not_found`，日志记录滚动次数和停止原因，流程继续下一模块或结束，无需人工继续。跳过只保存到任务日志和运行步骤，不创建问答结果批次，也不替换旧问答资料。下次新任务仍会寻找。入口不唯一、商品变化、验证和打开后的内容异常继续暂停处理。

```powershell
# 默认最多50个问题，逐题收齐页面可提供的回答
.\.venv\Scripts\python.exe main.py taobao detail --input "1050158363561" --questions
# 取消问题数量上限
.\.venv\Scripts\python.exe main.py taobao detail --input "1050158363561" --questions --all
# 先采100条有效评价，再采50个问题及各自全部回答
.\.venv\Scripts\python.exe main.py taobao detail --input "1050158363561" --reviews --questions
```

默认50限制问题数，回答没有条数上限；第50题的回答处理完才结束。不足50题时，确认列表末尾后完成。`--all` 取消问题上限；不承诺获取平台没有向当前账号展示的内容。选取未筛选的“全部”范围，兼容无显式全部标签或默认选中“全部46”等带独立数量的布局；名称与数量节点分开读取。不逐个点击话题标签；话题计数可能重叠，不能相加作为问题总数。

单次打开“查看全部问答”，在独立侧栏逐题点击“查看全部回答”，读取完整问题及各条回答；预览仅作核对，不计入正式回答。少量回答可能已经直接显示完整用户、正文等字段，没有展开或收起按钮，这种布局直接读取。只使用对应问题内的全文/更多回答入口。回答区若有独立滚动条则滚动回答区，问题列表加载则滚动侧栏；每次先保存当前批次，再滚动并等内容稳定。确认“收起”且回答全部展开，或确认无按钮的完整字段布局，同时没有更多入口或截断、无加载标志，或得到明确末尾/精确回答数证据，才能标记该题完整。没有按钮本身不是完整性证据，预览或仍被截断时依旧暂停。

问题标题数量仅作参考，不用于截断列表或单独判断采齐。所有已加载问题的回答处理完后，有明确末尾则记录 `end_of_list`；没有末尾文字时，必须确认侧栏确实到底，连续3轮滚动和等待后内容、位置、高度均稳定，没有新增问题或加载异常，才记录 `stable_bottom`。每轮底部复核最多等待5秒，并保留正常滚动间隔；出现加载状态时仍使用配置的完整加载等待预算。尚未到底却连续3轮不动、未知控件或异常加载仍保存进度并暂停。这里的完成范围是当前页面可提供的内容，标题数字不保证与实际一致。

“非常好”“可以”“十来张吧”等短回答保留，不应用评价的模板过滤。问答明细保留页面顺序、问题/回答ID（页面提供时）、完整正文、显示用户名、日期原文、购买规格、身份/购买时间标签和实际图片/视频链接；头像和信用图标排除，不下载问答媒体。相对日期保留原文，不猜绝对日期。页面未显示提问者和提问日期时为null。没有ID时使用文字/显示用户/时间及同批出现序号，并标记identity_exact=false；回答身份绑定父问题，可变媒体地址不参与身份。

输出在 `workspace/output/raw/taobao_details/<商品ID>/问大家/问答明细.json` 和 `问答明细.csv`；JSON按问题嵌套回答数组，CSV每条回答一行，重复问题字段。明确“暂无回答”的问题也保留一行；明确空态，或主页面显示0且没有问答入口和预览，才记录status=no_questions、message=无问答并写日志。侧栏只有标题0、没有列表或空态提示时仍按未加载处理；标题0同时存在实际问题或入口时继续采集。未加载/未知结构不是无问答。CSV为UTF-8 BOM、北京时间 `YYYY-MM-DD HH:mm:ss`，防止文字被当成公式；JSON保留原文和原始时间。

商品总JSON的 `questions` 保存数量、完成问题数、逐题完整性统计、限制/结束原因、文件路径和SHA-256，明细在独立文件中。每批保留 `history/<批次>/questions-progress.sqlite3`、`questions-progress.json`、`questions.json` 和导出的问大家目录。逐批事务保存，暂停/停止/异常写入 `questions_last_attempt`，不覆盖以前的正式完整结果；发布失败恢复旧文件夹，未登记或人工修改的文件不覆盖。正常完成清理进度JSON，历史数据库保留；当前不自动跨任务续跑。

操作串行，默认逐题间隔4～8秒；滚动间隔1.5～3秒、额外加载入口间隔4～8秒，每10题或连续操作5分钟休息30～60秒。休息仍可暂停/停止，人工暂停时间不计入连续操作预算；这些是节奏设置，不是免验证保证。在配置 `[taobao.pacing]` 中用 `question=[4,8]`、`question_rest=[30,60]` 调整对应间隔。验证码、未知弹窗、加载异常、商品或筛选变化沿用人工暂停规则，明确回复“继续”并复核后才恢复，不自动刷新或重放未确认的动作。单独执行问大家，也可在其他详情步骤最后执行；评价侧栏先正常关闭，再进入问大家。默认保留浏览器供后续检查，追加 `--no-wait` 正常完成后关闭。

问大家的“展开更多”也是回答加载入口，必须继续逐批点击并等待稳定，直到入口消失或得到明确末尾证据；不只识别“查看更多回答”。回答底部出现未知文字或按钮时先暂停，不能仅凭“收起”和当前10条回答就判定完整。标题数量与已取得问题数分别保存，`question_count_difference`表示两者差值，`title_count_is_reference_only=true`，`bottom_confirmation_rounds`和`completion_evidence`记录完成证据，`last_attention_reason`保留最近一次暂停原因。例如标题46、实际45时记录45题和差值1，达到末尾条件后可以正常完成。

人工清点确认的历史批次可以在验证文件哈希、数据库与导出内容一致、逐题回答完整后，生成新的 `manual_confirmation` 完成批次并发布；不重新采集或修改问答原文，保留来源批次、原始标题、确认数量、时间及说明。此操作只用于已明确人工确认且仅因列表无新增而暂停的可信批次，不会把未知结构或未完成回答自动改为完成。

## 参数代表什么

商品参数加在 `product open` 后面。文件和目录路径、带空格的文本都放在双引号中。

| 参数 | 含义 |
|---|---|
| `--keyword "粘毛器"` | 发布页搜索词 |
| `--category "完整类目路径"` | 用 `>` 分隔的完整类目；需要搜索词 |
| `--brand "无品牌/无注册商标"` | 选择品牌并进入填写页；需要类目 |
| `--main-images-dir "目录"` | 上传目录中的五张 1:1 主图 |
| `--portrait-images-dir "目录"` | 上传目录中的五张 3:4 主图 |
| `--detail-images-dir "目录"` | 按数字编号上传全部详情图 |
| `--video-file "文件.mp4"` | 上传商品视频，可省略 |
| `--product-info-file "文件.xlsx"` | 读取固定格式 Excel，填写分类、两个标题、五个属性、SKU、价格及编码；启用多件优惠，选择放入仓库 |
| `--sku-images-dir "目录"` | SKU图片目录，可省略；默认 Excel 同目录下的 `sku图`，需同时提供 Excel |
| `--submit` | 填写后点击提交到仓库；需要品牌及 Excel。不加时只填写 |
| `--no-wait` | 正常完成后自动关闭浏览器；中途人工提示仍会等待 |
| `--start` | 旧页面“开启”按钮兼容参数，尚未完成真实验证，正常流程不用 |
| `--port 8000` | 工作台端口，只用于 `web` 命令 |
| `--config "配置.toml"` | 指定配置文件，放在 `account`、`product` 等子命令之前 |

素材上传和 Excel 参数都需要先提供品牌，以进入商品填写页。Excel 使用现有固定格式的 `Sheet1`，运行前保存文件。

SKU 自动逐条填写：**SKU搜索主图、商品规格图片**共用同名图片（文件名去扩展名须等于完整销售规格名，扩展名不限）；**SKU搜索标题**使用 Excel 的“导购标题”。缺图、缺标题或未找到页面规格时，跳过对应字段并写明日志，其他可填字段继续；同名多图不猜选，页面已有图片保留并记录。

## 遇到弹窗怎么办

以上千牛命令已自动启用全局检测，无需增加参数；正常图片、视频、规格窗口按原流程使用。
主图、详情图和 SKU 图片上传期间会持续接管文件选择请求，防止额外的系统“打开文件”窗口；无需新增命令或参数。

| 提示 | 你的操作 |
|---|---|
| 已识别的“SKU管理页引导”公告 | 程序自动关闭；关闭失败则转人工 |
| 系统验证、未知弹窗或意外标签页 | 听到提示音后手动处理，在同一个 CMD 输入 `继续` 回车；没有反馈一直等待，弹窗仍在则继续等待 |
| 浏览器原生确认框 | 阅读终端中的内容，输入 `确认` 或 `取消` 回车；输入 `继续` 不会作出决定 |
| 当前等待或填写步骤超时 | 手动关闭弹窗后输入 `继续`，程序在当前浏览器恢复这个子步骤，完成后接着执行；已上传的素材不会重新上传 |
| 商品提交检查 | 人工核对页面和仓库后输入 `继续`，程序只复核结果，避免重复提交 |

日志：[run.log](../../workspace/logs/run.log)。未知弹窗的截图和同名 JSON 现场记录在 [screenshots](../../workspace/logs/screenshots)；原生确认框只保存 JSON。入口超时还可查看日志中的“已接管新标签页”和“操作页面”。
