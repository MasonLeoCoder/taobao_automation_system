# 项目目录与缓存清理指南

**最近核实：2026-11-03（北京时间）。适用项目：taobao_automation_system。**

本指南覆盖当前项目根目录、主要功能子目录和运行资料目录。任务编号、商品编号、日期等动态子目录按所属类别解释，不逐个展开。用途根据本机目录和代码引用核对；没有逐条核对正式数据库的文件引用、事件确认状态或正在运行的任务，因此不会把业务文件标为可直接删除。

本文是阅读和判断指南，编写本指南没有删除、移动文件或执行真实采集、分析。

## 1. 先看删除结论

| 标记 | 你应该怎么做 |
|---|---|
| ✅ 可以删除 | 只清理明确列出的范围；先满足该行写明的停止程序等前置步骤 |
| ⛔ 不要删除 | 正常使用或清缓存时保留；即使目录能重新生成，也不表示原数据能恢复 |
| 🔍 暂时不要删除，需检查 | 还需要确认引用、任务状态、是否有其他副本；检查前不删除 |

**父目录标为“不要删除”不妨碍清理其中明确标为可删的子项。例如保留 `src/`，但可以清理它下面的 `__pycache__/`。**

“可以重建”也不等于“免费且无损”：重新下载需要网络，重新扫码需要人工，重新采集不保证原内容仍在，重新运行 AI 可能再次计费。

## 2. 日常快速清理清单

| 路径 / 内容 | 结论 | 精确范围与删除前操作 | 删除后果、重建方式与成本 |
|---|---|---|---|
| `build/` | ✅ 可以删除 | 停止项目打包和安装后，删除整个目录；当前是 `lib/`、`bdist.win-amd64/` 等构建产物 | 源码启动不依赖它；下次打包重建，花费本地构建时间 |
| `src/`、`tests/`、`scripts/` 下的 `__pycache__/` | ✅ 可以删除 | 建议停止相关程序后，仅删除这些缓存目录和其中的 `.pyc`，保留 `.py` | 下次导入自动生成，不删除业务数据，无 AI 费用 |
| `.pytest_cache/`（如果以后出现） | ✅ 可以删除 | pytest 已结束后删除；不是删除 `tests/` | 丢失上次失败等测试缓存，下次测试重建 |
| 根目录 `test/` | ✅ 可以删除当前空目录 | 本次检查为空，未发现有效业务引用；删除前再次确认连隐藏文件也没有 | 不影响当前测试；**不是** `tests/`。以后有文件时须重新判断 |
| 普通旧 `.log`、旧错误截图 | 🔍 暂时不要删除，需检查 | 确认不在写入、不再用于排错且无引用；**排除 `logs/events/`** | 历史内容不会自动恢复，后续只能生成新日志 |
| `workspace/output/temp/` | 🔍 暂时不要删除，需检查 | 确认媒体任务状态及关联缓存，不能按文件年龄直接清空 | 可能丢失已下载内容和续传进度，重建可能重新下载 |
| 其他 `.json`、`.db`、`.sqlite3`、`.part`、`.lock` 文件 | 🔍 暂时不要删除，需检查 | 先按本指南找到所属目录和用途，不能只看扩展名 | 可能是任务状态、数据库、续传资料或锁，而非可丢弃缓存 |

本指南不提供一键递归删除命令，以免把同名的业务目录或新文件一起删除。

## 3. 项目根目录

| 目录 / 文件 | 对应内容 | 删除结论 | 删除影响与恢复方式 |
|---|---|---|---|
| `.git/` | Git 提交历史、分支、索引和仓库配置 | ⛔ 不要删除 | 丢失本地版本管理和未推送提交；远程不一定有完整副本，不能当缓存 |
| `.venv/` | 项目 Python 环境和已安装依赖 | ⛔ 不要删除 | 当前命令会失去 Python/依赖；需重建环境并重新安装，可能联网且版本不同 |
| `build/` | 打包工具生成的源码及资源副本 | ✅ 可以删除 | 按快速清单操作；不要在此修改正式源码 |
| `config/` | 正式本机配置与配置示例 | ⛔ 不要删除 | 可能失去数据库连接、路径及 AI 配置；默认值不能替代当前配置 |
| `docs/` | 使用说明、规范、数据库解释和历史验证记录 | ⛔ 不要删除 | 不一定阻止启动，但会失去操作依据、示例资料和追溯信息 |
| `scripts/` | 可复用的维护/验证工具 | ⛔ 不要删除 | 对应工具命令失效，需从版本库恢复 |
| `src/` | 正式 Python 源码、网页资源与安装元数据 | ⛔ 不要删除 | 程序功能损坏；仅清理明确的缓存子项 |
| `test/` | 当前为空的单数目录 | ✅ 可以删除当前空目录 | 删除前复核仍为空；不要误删复数 `tests/` |
| `tests/` | 自动测试、浏览器验收脚本及测试样例 | ⛔ 不要删除 | 影响回归验证；某些脚本依赖本地历史资料，不能随意直接运行 |
| `workspace/` | 当前业务输入、成果、登录资料、日志和开发归档 | ⛔ 不要删除 | 整体删除会丢失多种运行与业务资料 |
| `main.py` | 统一命令入口 | ⛔ 不要删除 | `python main.py ...` 无法运行 |
| `pyproject.toml`、`requirements.txt` | 依赖、安装、打包及命令声明 | ⛔ 不要删除 | 环境重建、安装或打包失去依据 |
| `.gitignore` | 防止缓存、业务文件和敏感配置被误提交 | ⛔ 不要删除 | 不直接删除数据，但会增加误提交风险；被忽略不代表可删 |
| `README.md`、`agent.md` | 项目入口说明和开发约定 | ⛔ 不要删除 | 丢失使用及协作规则 |

`.venv/Scripts/` 是 Python 和命令入口，`.venv/Lib/site-packages/` 是第三方库，`.venv/Include/` 是环境相关资源；整个虚拟环境按整体维护，不逐个删除库文件。`.git/objects/` 等也不是可手动清空的缓存。

## 4. config：配置，不是缓存

| 文件 | 用途 | 结论及影响 |
|---|---|---|
| `config/settings.toml` | 本机路径、数据库、浏览器、媒体工具等运行设置 | ⛔ 不要删除；包含本机有效值，不纳入 Git，不能指望从版本库恢复 |
| `config/ai.toml` | AI 服务、模型及相关设置 | ⛔ 不要删除；会影响分析行为；不要把实际凭据复制到文档或提交 Git |
| `config/settings.example.toml` | 基础配置模板 | ⛔ 不要删除；新环境安装和配置说明依赖它，不能覆盖本机正式配置 |
| `config/ai.example.toml` | AI 配置模板 | ⛔ 不要删除；用于说明配置，不等于本机有效配置 |

如果以后根目录出现 `.env`、`state.json` 或 `storage_state.json`，默认视为配置/登录资料，**不要当普通临时文件删除**。

## 9. workspace/models：本地模型辅助资源

**`models/deepseek-v4/`：⛔ 日常清理不要删除。** 当前保存的是分词器辅助资源，不是完整大模型权重。

| 内容 | 用途与删除影响 |
|---|---|
| `tokenizer.json` | 配置指向的本地分词器；代码会核对 SHA256。缺失或不可用时可退回保守 UTF-8 字节估算，可能改变预算、分组和容量判断，不代表行为保持一致 |
| `tokenizer_config.json` | 配套分词器说明资源，保留以便追溯 |
| `official.zip` | 原始下载包；🔍 暂时不要删除，需确认无需重装/核查且已有可靠来源后再决定 |

删除这些资源后程序不会自动替你下载恢复。重新获取需网络与正确版本；资源恢复本身不调用 AI，但重新发起业务分析可能产生费用。

| `analysis_workers/` | 分析工作进程互斥与运行资料 | ⛔ 不要删除 | 可能影响后台分析任务协调 |
| `web_collection_jobs/` | 保留的 Web 采集派发资料/兼容核对材料 | 🔍 暂时不要删除，需检查 | 正常队列已使用数据库，但显式迁移及运维核对仍有代码引用；不能根据“旧目录”直接删 |
| `video_tools/` | B站、YouTube等媒体记录、来源与缓存状态 | ⛔ 不要手工删除 | 优先对应工具的缓存清理能力；进行中、暂停、失败记录可能用于续传或重试 |
| `web_debug_service.json`（若存在） | 本地 Web 调试服务状态记录 | 🔍 暂时不要删除，需检查 | 先核对服务管理脚本及进程归属，不凭名称判断为无用文件 |

### 浏览器和媒体目录中的深层文件

- `browser_profiles/qianniu/`、`taobao/`、`bilibili/`、`douyin/`、`youtube/` 分别属于对应平台；其中的 Cache、Default、Local Storage 等由浏览器管理，**不使用“全项目删除 Cache”方式清理**。
- `browser_profiles/douyin_probe/` 等诊断资料：🔍 暂时不要删除，需确认没有验证脚本或浏览器仍在使用。
- `video_tools/<平台>/<环境标识>/<缓存编号>/`、按任务编号生成的目录，统一按父目录规则处理；编号本身不是过期标记。
- 媒体公共代码的闲置清理只处理符合状态与时间条件的终态缓存，并保护暂停、失败和进行中记录。人工直接删文件会绕过这些判断。实际闲置时间和临时目录以配置为准。

**MySQL 正式数据库的数据文件通常由 MySQL 服务管理，不一定在本项目目录内。删除项目中的 SQLite 或清理 workspace，既不等于清空 MySQL，也不等于完成数据库备份。**

只读核验归档完整性（**不是自动清理工具，也不能证明某个文件可删**）：

```cmd
.venv\Scripts\python.exe -B scripts\verification\workspace_audit.py
```

原始历史文件如果被删除，清单核验会报告缺失；不要为了让核验通过直接删除清单。归档与恢复方式见 [workspace 文件整理与核验](workspace文件整理.md)。

## 13. 清理前的五步判断

1. 找到完整路径，先查本指南；同名 storage、test、cache 可能用途完全不同。
2. 只有标为“可以删除”的明确范围才直接操作；其余先检查引用、任务和恢复来源。
3. 停止相关程序或任务后再清理，不以删除锁文件代替正常停止。
4. 记录删除对象及原因；业务资料需要保留可恢复副本，确认需要保留后再选择备份方式。
5. 清理后检查所用命令和历史页面；不要为了验证而自动重新付费分析、发布或采集。

新目录、改变的配置、升级后的功能都可能改变文件依赖。发现本指南未列出的目录或条目与实际不符时，默认 **🔍 暂时不要删除，需检查**，并更新核实日期。
