# 本地使用指南

用途：日常命令和可复制示例。更新日期：2026-10-28。详细参数见[完整命令参考](操作参考/命令参考.md)，其他资料见[文档索引](README.md)。

本轮测试按[功能逐项验收清单](功能逐项验收清单.md)逐项开展；每项人工确认后再进入下一项。以下命令说明用法，不改变测试顺序或通过状态。每轮执行先提供方案，用户确认后再执行；获批方案内的实施和本地验证连续完成，真实采集另行确认。

## 进入项目

在CMD中执行：

```cmd
set "TAOBAO_PROJECT=D:\VSCodeProject\taobao_automation_system"
cd /d "%TAOBAO_PROJECT%"
call "%TAOBAO_PROJECT%\.venv\Scripts\activate.bat"
```

以下 `python main.py ...` 均在该CMD和项目目录执行。首次安装见[项目说明](../README.md#快速开始)。

## 常用命令

| 命令 | 功能与范围 |
|---|---|
| `python main.py status` | 查看已实现及待实现能力 |
| `python main.py account login --platform taobao` | 登录淘宝，成功后保存会话并保留浏览器 |
| `python main.py account check --platform taobao` | 检查并复用淘宝会话，检查后关闭窗口 |
| `python main.py account login` / `account check` | 千牛登录或检查；默认平台为qianniu，与淘宝资料独立 |
| `python main.py taobao search --keyword "粘毛器"` | 只搜索并保存首屏摘要，不采集商品明细 |
| `python main.py taobao collect --keyword "粘毛器" --limit 8` | 销量排序后采集当前页前8条有效商品 |
| `python main.py taobao collect --keyword "粘毛器"` | 当前第一页已加载的全部有效商品，不自动翻页 |
| `python main.py taobao collect --keyword "粘毛器" --page 3 --limit 3` | 从第一页起采3页，每页最多3条；确认每页保存后才翻页 |
| `python main.py taobao collect --keyword "粘毛器" --page 3 --limit 3 --with-details` | 每页列表入库后逐个采集默认九模块，再翻页；本地验证通过，真实采集待确认 |
| `python main.py taobao detail --input "996877163053"` | 商品ID入口，默认采集详情九模块 |
| `python main.py taobao detail --input "996877163053" --parameters` | 仅采参数；指定任一功能开关后只执行选中的模块 |
| `python main.py tasks` | 最近50条任务 |
| `python main.py logs --limit 100` | 查询运行日志，每页1～500条 |
| `python main.py collections products --limit 50` | 查询已采集商品，每页1～200条 |
| `python main.py collections batches --product-id "996877163053" --limit 50` | 按平台商品号查询历史批次 |
| `python main.py web --port 8000` | 打开本机查询工作台入口，浏览器访问http://127.0.0.1:8000 |

`products --keyword` 查询标题文字或完整商品号，不是按来源搜索词筛选。Web支持来源关键词筛选；搜索方式筛选、实时推送和平台以图搜图仍待后续。

`--page`为从第一页起最多采集的页数，默认1，须为正整数；`--limit`是每页上限，省略时采各页已加载的全部商品。一次任务每页生成独立批次，跨页重复商品保留观察。确认末页可提前结束；翻页异常或验证暂停待人工，已保存页保留。汇总在`workspace/output/reports/taobao_list/<任务编号>.json`，不将数量上限解释为平台全量。

`--with-details`保留搜索页，串行打开标准详情链接并核对商品编号。同任务成功商品详情只采一次，列表每个位置仍保留；跨任务重新采集。默认评价100条、问题50个，每题可见回答不限；本轮不提供取消数量上限的列表开关。模块自身错误标红跳过并继续整批；验证码、登录和存储等全局阻断暂停，已保存数据保留。正常完成后详情标签逐个关闭，最后保留搜索页；加`--no-wait`正常完成后关闭浏览器。

## 全站筛选控件

搜索列表、商品库、任务/日志、采集配置、分析及资料查看页使用统一筛选外观。文字、日期和数值框统一尺寸与聚焦提示；普通下拉保留原有选项与选择方式，搜索型下拉支持输入检索；销量上下限成组显示，复选项与禁用状态清晰区分。查询、重置、分页和自动更新沿用原有行为。开发时修改公共样式即可同步调整所有引用页面，见[公共规范](变更记录/Web筛选控件统一规范.md)。

## 搜索词分析

启动工作台：

```cmd
.venv\Scripts\python.exe main.py web --port 8000
```

打开 [搜索词分析](http://127.0.0.1:8000/analysis/searches)，或从“搜索列表”的搜索词商品页/任务来源页进入。选择搜索词和采集范围，点击“应用筛选”；默认“日期范围汇总 · 每件商品取最新”，日期留空汇总全部历史，与搜索列表商品汇总一致；切换搜索词、修改日期和重置均恢复此默认范围。仍可手动选择最近一次或指定采集任务。勾选“排除已识别广告商品”时自动应用，概况、图表、店铺、关注列表和CSV统一排除所选观察中已识别的广告。未命中标识不等于已确认非广告。

可复制示例：[查看粘毛器的日期范围汇总并排除广告](http://127.0.0.1:8000/analysis/searches?keyword=%E7%B2%98%E6%AF%9B%E5%99%A8&snapshot=range&exclude_ads=1)。单次采集按商品取首次观察；`snapshot=range` 在日期范围内取最新观察，可能混合时间；先选观察再排广告，不借用旧数据补位。`since`/`until` 为北京时间日期，结束日包含在内。

“搜索关键词”展开后可输入部分文字查找，候选词会实时筛选并高亮匹配文字，显示匹配数量。点击对应词完成选择，再点“应用筛选”更新分析；清空检索只恢复候选列表，不改变已选词。支持方向键选择、回车确认、Esc收起及手机输入；无匹配时可清空或缩短输入。

“应用筛选”和广告筛选更新后定位到分析概览；切换数量口径定位到对应图表。点击价格柱、查询明细及明细翻页/跳页定位到商品明细，顶部筛选不会沿用旧的明细定位。

“各价位商品构成”按当前价格段列出商品数、实际数量展示档位、少量样本提示及合计。点击彩色档位可筛选对应价位和展示值/精度的商品，合计行的档位筛选全部有效价位；点击“查看X件”查看该价位全部商品。“1000人”“1000+人”“约1000人”分别统计；缺价不计入本表，无当前数量口径的数据另行提示。明细查询、翻页和CSV保留档位条件，清除明细筛选或重新选择价格柱可清理该条件。

“近30天收货人数 · 最常见档位”随当前搜索词、采集范围、日期及广告筛选重算，显示商品数量最多的展示档位及占比；全部并列档位分别显示，无有效数据时提示暂无数据。分母只含有可用近30天收货人数的商品，缺价商品也计入，精确/下界/近似分别统计。点击档位查看对应商品，明细和CSV保留该条件；卡片不受散点口径切换影响，最常见档位不表示表现最佳。

“商品发货地分布”位于价位构成表下方，默认收起，点击标题展开省份排名、商品数、占比及比例条；点击省份行展开城市分布。省份占比以当前筛选后的全部去重商品为分母，城市占比以该省商品数为分母，地区未记录也计入总数，缺价或没有收货人数不影响地区统计。数据来自每件商品当前所选列表记录的地区原文，表示商品数量分布。只有省份的记录显示“城市未记录”，无法明确归属的文字显示“地区待识别”，均可查看商品核对原文。地区已记录数包含有原文但待识别的商品。

点击地区的“查看商品”筛选下方明细，清理旧价格段、人数档位、搜索及店铺条件；查询、分页和CSV保留省份/城市条件，导出说明注明地区。清除明细筛选恢复全范围，重新点击价格柱或数量档位时清理旧地区条件。直接示例：打开 `http://127.0.0.1:8000/analysis/searches?keyword=粘毛器&region=浙江&city=金华#sa-products` 查看当前词的金华商品；`region`为省份简称，`city`为城市名称，可省略城市查看全省。模块折叠独立于原价位表，其他图表仍按完整样本统计。

“前50件商品竞争集中度”默认收起，跟随顶部搜索词、日期、采集范围和广告筛选。历史汇总先按每件商品取最新记录，单次范围沿用该次观察；最新记录无有效人数不使用旧记录补位。仅商品身份明确、可解析的近30天收货人数参与候选；精确值直接使用，“2000+”按2000，“约2000”暂不纳入，零值保留，缺价不影响计算。按人数值降序取前50件，同值依次按页码、slot_index、采集时间较新优先、观察ID升序取样，位置缺失排后；第50件跨出同值组时显示边界选入/未选入数。

CR3/CR10＝入选样本前3/前10件计算值之和÷入选样本合计，HHI＝各商品占比平方和×10000；三个指标使用同一份入选名单，仅在最终展示时舍入。HHI附实际N件均匀分布参照10000/N。不足50件按实际件数，CR3不足3件/CR10不足10件提示样本不足，合计为0不计算比例或HHI。“计算依据与入选名单”可展开逐件数值、占比、累计占比、来源位置和商品资料；“查看这3/10件”和“查看入选商品”筛选现有明细，默认按计算顺序，查询/分页/CSV保留名单条件，其他图表与本模块分母不随明细查询改变。CSV附名单口径、参与件数及合计，数据列保持不变。例：打开 `http://127.0.0.1:8000/analysis/searches?keyword=粘毛器&snapshot=range&exclude_ads=1&finding=top50&sort=concentration#sa-products` 查看历史汇总下的实际入选名单。结果明确为当前采集样本按收货人数展示下限计算，不等于真实销量份额。

产品类型分类已移除，旧链接的类型参数会自动清理，其余筛选继续保留。点击价格柱、样本发现可筛选下方明细；数量图表按口径和周期切换，保留零值及精度标记。“查看依据”打开侧栏，详情和批次链接可核对来源。“我的关注”只保存在当前浏览器标签页；“导出当前明细”导出当前筛选的全部商品或店铺，不受每页20条限制。价格未核对SKU，店铺按名称分组时可能合并同名店铺，不据此推算市场份额或真实销售额。

按用户确认，淘宝关键词搜索列表中可解析、未明示其他周期的收货人数按近30天统计，图表、商品明细和CSV统一显示“收货人数 · 近30天”。`1万+人收货`仍表示人数下界，不变成精确1万人；付款人数、已售件数和原文明示月度/累计的记录保留各自口径。旧“收货人数·未知周期”筛选在该组已不存在且有近30天组时自动更新并提示。新原始JSON记录解析版本2，原始CSV周期显示中文；历史原件和旧快照保留。更正范围见[实施记录](变更记录/收货人数近30天口径更正.md)。

价格图按当前完整样本自动生成约5～7段；有效价格不超过6种时按实际价位分组，同价显示一档，低价/高价尾部单列且全部保留。图上显示实际最低/最高价、中位数、有效数量及集中价位；悬停或键盘聚焦柱形可查看准确边界、数量、占比和实际价格。点击柱形后，明细搜索、排序、分页与CSV继续使用相同分段。切换搜索词、日期、采集范围或广告条件重新计算；旧价格段链接会恢复全部价位并提示。详情见[价格自动分段说明](变更记录/搜索词价格自动分段.md)。

## 详情模块与数量

`--input` 接受纯数字商品ID，或完整淘宝/天猫详情链接。不传功能开关时启用全部九模块；显式指定一个或多个时，只采指定模块。

| 功能开关 | 采集内容 |
|---|---|
| `--basic-info` | 详情标题、店铺、销量原文和页面展示价格；不枚举SKU，基本信息独立入库 |
| `--video` | 主图区域视频；确认无视频时记录无视频 |
| `--main-images` | 页面实际图集的全部主图，不固定为5张；未完成模块清理旧批次后从头重采 |
| `--skus` | 仅SKU组合、规格价格与规格图；未确认价格保留原因，不改基本信息 |
| `--parameters` | 动态参数名称、完整原文、顺序和原始HTML |
| `--detail-images` | 图文详情模块实际图片，按顺序保留原件 |
| `--review-summary` | 评价数量、好评率范围、总结标签 |
| `--reviews` | 默认最多100条有效评价；模板好评跳过，买家媒体只存链接 |
| `--questions` | 默认最多50个问题；每题采页面提供的全部可见回答 |

`--all` 取消已启用的评价/问题数量上限，不代表选择模块。单独使用 `--all` 仍是默认九模块。`--no-wait` 仅在正常完成后关窗，遇人工验证仍等待。

问大家入口每次向下滚动约四分之三屏后重新检查，最多10次；连续3次页面位置和高度不变时提前停止。停止寻找后仍没有“查看全部问答”，日志记录次数和原因，本次问大家标记“已跳过”，继续下一模块或正常结束任务，不弹人工处理提示。跳过不等于“无问答”，不覆盖旧问答资料，下次新任务仍重新寻找。登录验证、商品变化、入口不唯一、结构异常，以及打开后的采集异常继续按原规则处理。

主图按用户指定规则，直接读取主图区域缩略图DOM中的`img.src`：按完整地址去重，保留第一次出现的顺序，连续编号为`1、2、3…`并保存到`1-1主图`。`//`地址按当前页面补全协议；保留查询和压缩后缀，因此下载的是DOM地址对应的图片，不自动换成原图。参数入口无图片，自动跳过；第一张不再按视频封面猜测排除。商品数据内另外两套图片列表不参与采集或阻断。例如6个图片节点为A、A、B、C、D、E，最终保存5张，编号1～5，对应原位置1、3、4、5、6。去重后图片数量、地址或顺序在下载中变化时仍暂停核对。

采集代码修复后，新发起的任务使用新规则。已经运行或暂停的采集进程不会因Web重启自动换代码；应先在页面停止旧任务，再重新发起“采集所有”，已确认完成的模块会跳过。调试期间由助手自动重启Web，既有采集任务仍独立运行。

以下为默认九模块的完整CMD示例，保留100条评价、50个问题的默认上限：

```cmd
python main.py taobao detail --input "https://detail.tmall.com/item.htm?id=996877163053"
```

默认保留浏览器供查看，查看完关闭窗口再核对任务最终状态。阶段完成时任务可能仍为running，不能仅凭该状态判断采集是否失败。完整字段与文件规则见[命令参考](操作参考/命令参考.md#淘宝单商品详情页入口powershell)和[详情采集规范](采集规范/淘宝详情页采集字段清单.md)。

## 停止、续采和手动补采

关闭采集浏览器或点击停止后，已保存模块保留，整次执行和补采队列停止。网页“商品采集”的最近任务可查看恢复计划，核对清理范围后继续；失败项可点击单模块重新采集，当前任务结束后执行。服务重启不自动启动队列，须点击“继续队列”。

续采沿用原页数、商品清单、模块和数量范围；完成或入口未找到的模块复用，已标红跳过的模块等待补采。停止时未完成的模块删除对应旧明细及专属文件，创建新批次从头采集，不补齐旧批次，也不复用旧部分图片。已有完整历史资料与其他模块保留。

CMD先将TASK_ID设置为最近一次执行的真实任务编号，再执行以下两行；预览命令不启动浏览器：

```cmd
set /p "TASK_ID=请输入原任务编号："
python main.py taobao resume --task-id "%TASK_ID%" --preview
python main.py taobao resume --task-id "%TASK_ID%" --no-wait
```

没有可靠恢复计划的旧任务只能选择具体模块重采。入口未找到显示黄色警告，按无需采集完成；失败跳过显示红色错误；整批结束不等于全部资料完整。各模块保留实际采集时间。详细边界见[实施记录](变更记录/采集恢复与异常跳过实施记录.md)。

## 核对数据库与文件

本机正式库为 `taobao_automation`，独立测试库为 `taobao_automation_verify`；任务、日志和结构化采集使用MySQL。数据库、CLI和Web统一北京时间（UTC+08:00），原始来源时间不重写。

```cmd
python main.py database check
python main.py collections products --limit 50
python main.py collections batches --product-id "996877163053" --module parameters --limit 50
```

## 人工处理与任务控制

遇到验证、未知弹窗或访问异常，先在保留的浏览器处理，再在运行终端输入 `继续`；空回车不放行。原生确认框先明确输入 `确认` 或 `取消`，再继续。没有反馈一直等待，不自动重放发布或上传。

淘宝任务也可以从另一个已进入项目的CMD控制：

| 命令 | 作用 |
|---|---|
| `python main.py taobao pause` | 在下一检查点暂停 |
| `python main.py taobao continue` | 向当前人工提示发送继续，页面复查通过才恢复 |
| `python main.py taobao confirm` / `taobao cancel` | 明确决定当前原生弹窗，随后还需continue |
| `python main.py taobao stop` | 请求停止，保留已采资料，不启动第二个浏览器 |

打开 http://127.0.0.1:8000/modules/collection 或点击左侧 **商品采集**：

完整网页示例：进入 **商品采集 → 关键词采集**，填“粘毛器”、页数“3”，关闭“不限数量”并填每页“3”，按需勾选“连带采集商品详情”，核对下方范围后点击 **开始采集**。这与命令 `python main.py taobao collect --keyword "粘毛器" --page 3 --limit 3 --with-details --no-wait` 的采集范围一致。网页默认结束后关闭该任务的采集窗口。

最近任务与底部任务栏自动更新，显示已保存页数、商品记录数或详情模块进度；刷新后恢复在途任务。可查看日志、结果或停止任务。登录/验证仍需在淘宝窗口处理，再在网页明确选择继续；原生弹窗需明确确认或取消。重复提交相同在途配置复用任务；其他配置需等待当前任务完成或停止。网页写操作仅限本机来源，需要同时启用 MySQL 任务与采集存储。

滚动评价后的正常间隔为随机 **1.5～3秒**。“运行日志”中的“操作间隔等待”是一条历史事件，不是实时倒计时。若业务已中断而浏览器保留现场，采集任务栏和日志页会显示具体原因，并保留停止入口；没有“继续”按钮时，请先停止当前任务，再重新发起采集。结果尚未入库时不会显示采集成功，中文诊断与英文停止原因分开保存；已采记录和待入库流水继续保留，重新采集不等于修复旧流水。

- **搜索列表**：打开 http://127.0.0.1:8000/collections/searches ，首页按搜索词分类，汇总历次任务、页批次、列表记录数、跨批次去重商品数和最近采集时间；点击“查看商品”直接进入商品汇总，查看标题、价格、销量、店铺、发货地、广告标记、采集时间和详情资料情况。“全部采集记录”保留每次观察，“查看历次采集”另行进入任务列表。跨页重复观察分别保留。每个商品同时显示已有详情资料情况和本次关联情况。
- **商品详情**：打开 http://127.0.0.1:8000/collections/details ，独立展示已有详情批次、详情入口或运行尝试的商品，不要求有搜索列表记录。仅入口或失败运行不算已有详情内容；纯列表商品在搜索列表中查看。
- **列表到详情**：从列表位置进入，优先使用明确关联的详情运行；同任务同商品的其他位置仅标记“同任务已有详情，本位置非确认入口”。没有本次关联时，可查看其他时间已有资料，页面明确标注。未保存的本次模块不会自动用旧结果填补，历史批次可手动切换。
- **详情回查来源**：“关联搜索列表”展示该商品出现过的列表观察，可以返回对应批次、网页页码和位置。同一商品出现过不等于该次列表是详情采集入口；缺少关系不根据标题补造。没有列表资料的详情照常展示。
- **状态与原件**：有效资料、部分尝试、仅入口和最后一次运行状态分别展示；各模块按实际范围说明，确认无视频等属于明确结果。缺失或校验变化的原件显示提示，不删除采集记录。
- **回查任务和日志**：页面提供关联任务、日志及返回来源页面入口；回到列表时保留筛选、排序和网页页码。

所有网页列表每页20条，支持页码跳转、排序，边界按钮置灰不可点击。SKU规格图与明细同行展示，跟随规格统一分页。任务默认按开始时间从新到旧，日志默认按发生时间从新到旧；命令行仍使用原有数量和游标规则。详情页“曾出现的搜索词”只筛选商品在列表中的出现记录，不把详情归属于该次搜索。

网页已支持前文的采集配置、所选详情模块采集和重新采集；查看已有资料不会触发平台操作。当前没有自动断点续采入口，重新采集按新任务范围执行。

### 日志筛选

打开 http://127.0.0.1:8000/logs ，输入任务编号、选择中文日志级别，并通过日期时间控件设置起止时间。网页按北京时间处理，无须填写时区；旧的带时区时间链接仍可使用。点击“今天”“最近24小时”“最近7天”会立即按对应范围查询，并保留任务与级别条件；“今天”为北京时间当天零点至当前时间。翻页保留选定的实际起止时间及任务、级别条件；使用统一的20条页码分页，没有上一页或下一页时按钮置灰且不可点击，超出总页数的请求返回不存在页面。旧网页游标链接回到第1页。“重置”清除全部筛选。大屏横向排列，小屏自动换行。

命令行与 `/api/events` 接口的时间参数仍须包含时区。此变更不包含日志实时刷新。

日志表格显示中文任务名称、完整任务编号和中文执行步骤，发生时间使用“年-月-日 时:分:秒”的北京时间格式。悬停任务名称或步骤可查看对应原始代码；未知名称或步骤保留原文，缺失内容明确显示未记录。日志级别同时显示文字与颜色：调试灰色、信息绿色、警告黄色、错误浅红色、严重错误深红色。任务名称按任务编号关联读取，缺少关联任务的日志仍保留显示。

### 列表排序

点击带箭头的表头切换升序、降序；当前排序列会高亮并显示方向。排序针对全部符合条件的记录，在数据库排序后再按每页20条分页。切换排序回到第1页，翻页和筛选保留排序条件。

- 任务：支持名称、状态、开始时间、结束时间和结果排序。
- 日志：支持发生时间、任务名称、级别和提示内容排序；日志级别按调试、信息、警告、错误、严重错误排列。
- 商品资料：支持标题、最近列表价格、已采模块数和最近采集时间排序；价格使用对应列表观察的可靠数值，不按价格原文文字比较。
- 搜索记录：支持来源关键词、开始采集时间、保存批次数、列表记录数和任务状态排序。
- 商品采集历史：支持采集时间、模块和状态排序。
- 采集明细：支持原始顺序和内容排序；按实际字段提供价格、参数值、用户或采集时间排序。图片和视频使用“素材排序”切换原始顺序的正序、倒序；SKU规格图跟随对应规格行排序和分页，不再提供独立图片列表。

时间列表默认最新在前，商品明细和素材默认保留原始顺序；空时间、未确认的价格始终排在最后。评价、回答中的“几天前”等日期原文不推算成精确时间，时间排序使用已保存的采集时间。

所有数据表格支持整行悬停高亮：鼠标移到某条数据的任意单元格时，当前整行显示浅绿色背景，移开后恢复。表头排序提示保持原样，空结果提示不高亮。

运行日志的事件类型使用中文名称显示，例如 task_finished 显示“任务结束”、collection_saved 显示“采集数据已入库”。仅鼠标悬停在“任务结束”等中文类型文字上时显示英文代码提示，也可用键盘聚焦类型文字查看；悬停日志级别标签或单元格空白处不显示代码。整行高亮与代码提示可同时显示。未知类型保留原文，数据库中的 event_type 不作修改。“任务结束”不代表任务成功，需结合任务状态判断。

搜索词分类页每页20个词，分类内任务列表每页20条。未记录搜索词（NULL或空字符串）的批次归入独立分类，不从标题推测；字面值“搜索词未记录”仍作为实际搜索词单独分类。同一任务包含不同搜索词时，分类内只读取所选搜索词的批次。日期筛选用于分类及分类内对应批次统计；无任务归属的批次按独立记录计数。进入分类保留父页日期条件，返回时保留父页筛选、排序和页码。

### 搜索词商品展示

搜索词分类的“查看商品”默认打开商品汇总：同一个已确认商品在当前搜索词和日期范围内只显示最近的一条列表观察，按批次采集时间、批次编号、观察编号确定先后。标题、价格原文、价格数值、销量、店铺、发货地和广告标记均来自该条观察，不拼接不同时间的数据。标题/店铺筛选在最新观察选出后执行，不因旧记录命中而回退旧价格；如需查询旧标题或店铺，切换到“全部采集记录”。

商品汇总、全部记录均每页20条并支持排序；时间默认最新在前，价格按可靠数值排序，未知价格放最后。日期范围内出现次数保留重复观察；未确认商品身份的记录单独展示，不按同名合并。标题/商品ID、店铺、日期和详情资料情况可筛选，没有详情的商品仍可正常查看。

每行可进入对应观察的详情资料、当前搜索词下该商品的全部采集历史、平台商品及来源页位置。详情关联按该行实际观察核对，不把旧资料说成本次采集。缩略图只使用明确关联同批次同位置且有已核对文件索引的列表图片，否则显示占位。统计栏总数按当前搜索词和日期范围，分页栏显示当前筛选结果数。

分类页条件带入商品页，返回保留筛选、排序、页码；“查看历次采集”作为辅助入口保留。整个查看流程只读，不启动采集或改写历史价格。


## 列表主图下载

后续执行列表采集时默认下载每条商品卡片主图，无需额外开关。当前页图片处理并入库后，才继续详情或翻页。图片逐张处理，最多尝试3次；失败保留商品，结果提示成功数、失败数和缺地址数。新JSON为格式5，CSV增加“主图下载状态”和“主图本地路径”。列表主图独立于详情主图，网页按对应批次和位置显示，点击图片在本页放大，预览内可另行打开原图；商品汇总只显示最新列表观察自身的图片，不从旧批次填补。

完整示例（执行真实淘宝采集，需按当前验收安排单独确认）：

```cmd
.venv\Scripts\python.exe main.py taobao collect --keyword "猫抓板" --limit 3 --page 1 --no-wait
```

历史列表缺失图片使用一次性临时脚本补充，完成后删除脚本；项目不提供长期历史补下载命令。正式图片、数据库关联与本次执行报告保留，网页刷新即可查看。补充图片不会改变原商品信息及采集时间，也不能保证旧地址现在返回的内容与原采集时完全一致。


搜索词商品页新增“广告识别”筛选：全部、已识别广告、未命中广告规则、未确认或未记录。未命中规则不等于确认非广告；未确认包含unconfirmed和数据库空值。商品汇总先取范围内最新观察再筛选广告状态，全部采集记录按每条记录自身状态筛选。分页、排序和切换页签保留条件，重新查询回到第1页；重置清除广告筛选。此项仅查询，不修改数据库字段或记录。


Web操作入口统一使用文字按钮：主要查看和查询为深绿色，历史/日志/任务为浅蓝色，来源追溯为浅紫色，外部平台跳转为浅橙色并保留箭头，返回/重置/刷新为灰色描边。表格按钮采用紧凑尺寸，商品页操作列纵向排列、文字不折行；导航、页签、排序表头和分页保持原交互。鼠标悬停和键盘焦点均有提示，颜色之外仍保留明确操作文字。


## 列表销量排序与范围筛选

列表展示商品缩略图／标题／ID、价格、销量、店铺／发货地、来源与全部关联搜索词、有效模块数、最近记录和操作。价格、销量和店铺优先来自同一条最近已发布列表观察；即使其中有空字段，也不拼接其他时间或详情的字段。没有列表记录时，使用已完成基本信息批次的原文，并标明“详情页”及实际观察时间。详情主图优先，没有可用详情缩略图时回退最近列表同位置的本地图片；图片沿用本页点击放大。

可筛选标题／完整商品ID、当前显示的店铺、曾出现的精确搜索词、商品来源、资料情况、最近记录日期、销量上下限。筛选搜索词不会把显示快照切回旧搜索；点击行内搜索词，可查看该商品在此词下的全部列表记录。最近记录取已发布列表、详情保存、详情访问、详情运行中的最新时间；未记录时间置后。日期筛选对应该列，结束日期包含当天。每页20条，支持商品、价格、销量、店铺、有效模块数和最近记录排序。

价格数值排序及销量范围使用现有列表结构化值；只有详情原文或缺少数值的记录不当作0，排序时置后，填写销量区间时不会匹配未知数量。上下限均包含，留空不限，0为实际零值；“1000+”按展示下界1000参与，不代表真实销量上限。有效模块数和最近详情运行结果分开显示，失败不会清除已有有效资料；明确无内容的有效模块计入完成。

商品标题为普通文字，不再点击跳转；点击操作列绿色“查看详情”按钮进入当前商品，或点“查看采集历史”查看历史。返回商品库保留筛选、排序和页码，商品图片仍可在本页点击放大。行内“补采未完成模块（N）”直接复用剩余模块后台任务，启动时重新核对计划，跳过已有完成和明确无内容模块；采集中沿用全站进度、人工继续／停止弹窗和任务互斥。补采结束后按钮按实际计划更新，查看资料页可见最新保存结果；刷新商品库可更新整行信息。浏览或筛选不自动采集。

商品库最右侧“操作”列固定在表格右侧，包含表头、查看详情、查看采集历史和补采按钮。窗口较窄时，其他列仍在表格内横向滚动，操作按钮始终可见；固定区域保留背景、分隔阴影和整行悬停高亮，不会透出底下的滚动文字。该样式只用于商品库。

启动命令（CMD，`--port`指定本机服务端口）：

```cmd
python main.py web --port 8000
```

完整查看示例：打开 `http://127.0.0.1:8000/collections/details?origin=list&sort=sales&order=desc`，查看仅有列表来源的商品并按销量倒序。调试期间助手已自动重启服务，直接刷新即可，不需要升级数据库或重新采集。

### 资料来源与最近详情入口

商品库“来源”列及筛选名称改为“资料来源”。上方的“列表与详情”等说明已有资料类型；关联搜索词只表示商品曾经出现在这些搜索列表中，不表示最近详情从该词进入。

同一栏下方单独显示“最近详情入口”及实际入口时间：有独立详情任务和可核对ID／URL输入记录时显示“直接采集”；入口明确关联同任务、同商品的已发布列表观察时显示“搜索列表进入”，并注明实际入口搜索词；缺少关联、证据不足或归属冲突显示“入口未记录”。仅有列表或商品身份时显示“尚无详情记录”。这个分类不表示采集已经成功。

启动命令（CMD，`--port`指定本机端口）：

```cmd
python main.py web --port 8000
```

完整查看示例：打开 `http://127.0.0.1:8000/collections/details?keyword=851580909964`。此次调试修改后已自动重启Web，刷新即可，无需数据库升级或重新采集。


## 2026-10-27 统一申请与队列

网页“采集任务”和“采集等待队列”统一读取MySQL，包括网页申请、命令行采集及已核对的旧派发记录。当前有任务时可点击“加入采集队列”；入库成功才显示已提交，启动失败也保留申请。仅搜索/仅打开页面不登记采集申请。

“采集任务”按申请时间从新到旧展示全部申请，每页20条，可通过“上一页／下一页”翻页，并按等待启动、运行中、需要人工处理、已停止、已结束、失败筛选。切换状态回到第一页；自动刷新及整页重载保留当前页和筛选，记录减少导致最后一页消失时回到最后有效页。底部当前任务独立显示，不受历史翻页影响。“已结束”包含正常结束但有跳过、模块错误或资料待核对的执行，具体结果仍看卡片说明。左侧“任务记录”继续用于实际执行历史，不替代未启动申请列表。

完整只读查看示例：打开 `http://127.0.0.1:8000/modules/collection?jobs_page=2&jobs_status=stopped`，查看已停止申请的第2页；不足两页时显示最后有效页。翻页和筛选不会开始采集，原有开始、停止、恢复计划与补采入口继续适用。

点击任务卡“查看任务说明”后，自动刷新会保留展开状态和说明内部的滚动位置；手动收起后保持收起。翻页或切换状态再返回，也按各任务分别保留阅读状态。该状态只保留在当前网页内，整页重新打开后默认收起，不写入数据库。

在同一历史页向下阅读时，自动刷新保持当前任务在屏幕中的位置，不回滚到筛选区；新申请出现在上方时，当前任务仍在本页就继续保持阅读位置。刷新请求等待期间可继续滚动，以响应到达时的最新位置为准。主动翻页或切换状态正常展示所选结果，不套用上一页的滚动位置。

“查看恢复计划→按此计划继续”针对选定任务；“继续队列”恢复其他等待申请。停止、关采集浏览器、全局异常及服务重启后队列暂停，正常新申请继承暂停。关闭网页不停止后台任务。

尚未执行的暂停申请可直接点击任务卡或底部状态栏的“开始本次采集”，只启动该申请，其他暂停申请继续保留。队列暂停且无采集运行时，表单按钮显示“保存采集申请”；保存后使用上述开始入口。队列控制位于历史记录上方；“继续队列”用于恢复全部等待申请。已执行后停止的任务使用“查看恢复计划”，不重新启动原申请编号。

断库时不接受新采集，不自动开浏览器；正在运行的任务保留可靠缓冲并在检查点等待。网页显示最后确认时间，已知活跃采集仍可紧急停止，恢复连接先补写停止和队列暂停。继续/确认不能跳过入库，补写不重放页面动作。

旧派发记录升级示例（项目CMD）：

## 登录状态文件保存失败

登录状态先完整写入同目录的独立临时文件，再替换正式文件。Windows拒绝访问或文件占用（错误码5/32/33）时，总计最多尝试3次，重试间隔0.2秒、0.5秒；只重试文件替换，不重放登录、翻页或采集动作。重试记录黄色警告，持续失败记录红色错误，说明目标/临时文件、阶段、尝试次数及系统错误码，不输出Cookie或localStorage内容。

持续失败会保留原登录文件，采集任务按原规则结束为失败并暂停队列；排除占用或权限问题后，通过任务卡“查看恢复计划→按此计划继续”续采。已有失败任务保留原错误，不因本次程序修复改成成功。淘宝与千牛仍使用各自独立路径；不会删除原故障taobao.tmp，也不会自动清空登录状态或调整文件权限。

## 列表续采的校验和保留现场

已保存列表页的检查点完整保留原批次、原件路径、商品清单和json_sha256。查看恢复计划时只读核对批次归属、文件登记、实际文件与原范围；旧检查点缺少校验值但原件一致时，预览提示“确认续采后补齐并复用”，不会修改原计划。真正补齐发生在新续采执行中，旧任务及原错误保留；文件不存在、内容变化或归属不一致仍阻止续采。

列表任务卡分别显示“原计划已保存/累计记录”和“本次执行已处理页数”。前者包括历史已入库页，后者是本轮流程已确认的页数（可含复用页），不等于本次新下载数量；本轮显示0页不表示历史资料丢失。

可见浏览器运行中出现NeedsAttention时保留现场。能够在页面处理的验证仍使用原人工反馈流程；业务已中断的数据异常显示“采集已中断（保留现场）”，只能停止或关闭窗口，不能点击继续绕过校验。保留现场期间仍占用当前采集资源；处理后停止/关窗，再从最新执行查看恢复计划。预览或执行前已经发现原件问题时直接阻止启动，无需先打开浏览器。
