# 本地使用指南

以下初始化和商品填写示例使用 CMD；PowerShell 的淘宝搜索步骤见下方“淘宝关键词搜索本地测试”一节。

先在 CMD 执行以下三行，进入项目并使用已有虚拟环境：

```cmd
set "TAOBAO_PROJECT=D:\VSCodeProject\taobao_automation_system"
cd /d "%TAOBAO_PROJECT%"
call "%TAOBAO_PROJECT%\.venv\Scripts\activate.bat"
```

## 命令可以执行什么

| CMD 命令 | 功能 |
|---|---|
| `python "%TAOBAO_PROJECT%\main.py" account login` | 登录千牛；需要时扫码，成功后保存登录状态 |
| `python "%TAOBAO_PROJECT%\main.py" account check` | 检查登录是否有效 |
| `python "%TAOBAO_PROJECT%\main.py" account login --platform taobao` | 淘宝买家端独立登录，在新浏览器中手动选择登录方式并完成验证 |
| `python "%TAOBAO_PROJECT%\main.py" account check --platform taobao` | 只检查淘宝登录状态，与千牛分开 |
| `python "%TAOBAO_PROJECT%\main.py" taobao search --keyword "粘毛器"` | 首页搜索，确认首屏后保存摘要并保留窗口；加 `--no-wait` 可确认后关闭 |
| `python "%TAOBAO_PROJECT%\main.py" taobao collect --keyword "粘毛器"` | 搜索后点击销量，确认排序再读取第一页，保存 JSON 和 CSV；默认不限制当前页条数，可加 `--limit 20` |
| `python "%TAOBAO_PROJECT%\main.py" taobao pause` | 在另一个 CMD 请求暂停当前淘宝任务，在下一检查点等待人工反馈 |
| `python "%TAOBAO_PROJECT%\main.py" taobao stop` | 请求停止当前淘宝任务，不启动第二个浏览器 |
| `python "%TAOBAO_PROJECT%\main.py" taobao continue` | 处理后向当前提示发送继续，未通过页面复核则保持暂停 |
| `python "%TAOBAO_PROJECT%\main.py" taobao confirm` / `taobao cancel` | 明确决定当前原生弹窗，随后还需继续指令恢复后续业务 |
| `python "%TAOBAO_PROJECT%\main.py" product open` | 打开商品发布入口；加下面的参数执行填写 |
| `python "%TAOBAO_PROJECT%\main.py" product open --keyword "粘毛器" --no-wait` | 仅复测发布入口和搜索，结束后关闭浏览器 |
| `python "%TAOBAO_PROJECT%\main.py" status` | 查看已实现和待实现功能 |
| `python "%TAOBAO_PROJECT%\main.py" tasks` | 查看最近 50 条任务记录 |
| `python "%TAOBAO_PROJECT%\main.py" web --port 8000` | 启动本地工作台，访问 http://127.0.0.1:8000 |
| `python "%TAOBAO_PROJECT%\main.py" product --help` | 查看商品命令帮助 |

淘宝 `account login --platform taobao` 登录成功后保存会话并保留窗口，手动关闭淘宝浏览器才结束任务。
若需自动关闭，可加 `--no-wait`。`account check --platform taobao` 仅检查状态，检查结束后自动关闭窗口。
淘宝登录和检查遇到验证、未知弹窗等会保留现场，记录截图并提示。请处理后在任务所在 CMD 输入 `继续` 回车，程序复查通过后恢复。
空回车或 `已完成` 不放行；输入 `停止` 结束任务。原生确认框先输入 `确认` 或 `取消`，再输入 `继续`。
同一个阻断仅响一次提示音；等待不设超时。若输入通道关闭，仍可用另一个 CMD 执行 `taobao continue`、`taobao confirm`、`taobao cancel` 或 `taobao stop`，不会因此自动继续。
`taobao search` 只确认首屏并保存摘要；`taobao collect` 另可保存第一页已加载的商品字段。2026-10-21 已分别完成真实自动搜索和 20 件商品字段采集验收；本阶段均不翻页。

淘宝普通启动连接模式可在 `config/settings.toml` 的 `[taobao]` 下设置 `browser_channel="chrome"` 和 `browser_mode="native_cdp"`。需要本机已安装 Chrome、`headless=false`；继续使用淘宝独立资料，并保留人工验证守卫。不设置模式时使用原启动方式；一次成功不代表今后无需验证。

## 淘宝关键词搜索本地测试（PowerShell）

本机已配置系统 Chrome 的普通启动连接模式，沿用已有淘宝独立登录资料，无需重新修改配置或激活虚拟环境。

先关闭上一次保留的淘宝测试窗口，并等待旧任务结束。同一套浏览器资料不能同时启动两个任务；如果还有千牛浏览器任务，也要先结束。

打开 **PowerShell**，复制以下两行执行：

```powershell
cd D:\VSCodeProject\taobao_automation_system
.\.venv\Scripts\python.exe main.py taobao search --keyword "粘毛器"
```

更换关键词时只修改引号里的文字。程序会复用淘宝登录资料；会话失效时，按页面提示手动完成登录。

成功判断：程序自动输入关键词并提交一次搜索，首屏商品加载后，终端显示“搜索结果已确认并保存”。默认保留浏览器供你检查；关闭搜索标签页后任务结束。需要确认保存后自动关闭时，在命令末尾添加 `--no-wait`。

遇到验证或未知弹窗时，程序记录现场并暂停。请在当前浏览器中手动处理，成功后在任务所在终端输入 **`继续`** 并回车；程序复核通过后才恢复。不要关闭窗口后再输入继续。验证失败或决定结束时，在人工提示处输入 **`停止`**。

如果原终端无法输入，另开 PowerShell，同样进入项目目录，处理完成后执行：

```powershell
.\.venv\Scripts\python.exe main.py taobao continue
```

需要停止当前任务时，在另一个已进入项目目录的终端执行：

```powershell
.\.venv\Scripts\python.exe main.py taobao stop
```

提示“已有任务运行”时，先结束旧任务，等待其退出后再启动，不要同时打开第二套相同资料。

| 测试记录 | 项目内位置 |
|---|---|
| 搜索摘要 | `workspace/output/raw/taobao_search/<任务编号>.json` |
| 搜索结果截图 | `workspace/logs/screenshots/taobao-search-<任务编号>.png` |
| 搜索动作和验证事件 | `workspace/logs/taobao/<任务编号>.jsonl` |

`search` 摘要中的已识别商品链接数量用于判断结果就绪，可能少于页面卡片数，不代表搜索总量。需要商品表格时使用下面的 `collect` 命令。

## 淘宝第一页商品采集（PowerShell）

先关闭上一次保留的测试浏览器并等待任务退出，然后执行：

```powershell
cd D:\VSCodeProject\taobao_automation_system
.\.venv\Scripts\python.exe main.py taobao collect --keyword "粘毛器"
```

程序沿用淘宝独立登录资料，从首页提交一次搜索，随后自动点击“销量”，确认该页签已选中且商品列表更新，再读取第一页已经加载的商品卡片。保存后显示件数和两个文件的完整路径。默认保留窗口供核对，关闭搜索标签页结束任务；需要保存后自动关闭，在命令末尾加 `--no-wait`。

正式流程为：**复用登录 → 输入关键词并搜索一次 → 等待列表加载 → 点击销量一次 → 核对排序和列表更新 → 同页分段加载主图 → 逐格分类并采集 → 保存 JSON/CSV → 保留浏览器**。默认按销量，无需增加命令参数；`taobao search` 仍只搜索并保存摘要，不执行采集排序步骤。

排序按钮已经选中“销量”时直接复核复用，不再次点击。网址不一定变化，因此同时读取真实排序页签的选中状态；点击后检查商品内容变化、列表重新建立或页面导航等更新证据，并等待加载提示消失。排序前、结果确认后分别复用 `before_search`、`search` 的间隔配置，默认均为 2～4 秒。

排序入口缺失、重复、不可用，或点击后未能确认排序/列表更新时，记录现场并暂停，请人工处理后输入 `继续`。不会自动再次点击销量、重新搜索或按综合排序继续采集。明确无结果的页面保存空批次，无商品可供排序。

默认不限制条数，采集当前第一页已加载的全部有效商品。只有显式添加 `--limit 正整数` 时才限制最多保存的有效商品数量，例如 `--limit 20`；没有固定 50 件上限，0、负数和非整数会在启动浏览器前报错。此处“不限制”仅指当前页商品数量，尚未增加翻页。

首屏外主图可能延迟加载，程序会在同一页分段滚动并按 `scroll` 间隔等待，确认显示主图节点出现后再读取；不翻页、不打开详情。滚动和短等待均有上限，仍未取得的字段明确标记；指定上限但商品不足时按实保存，不承诺采满。

| 保存内容 | 说明 |
|---|---|
| 商品ID、完整标题、主图、商品链接 | 从列表内单个格子读取；标题优先用完整 `title` 属性，主图只取显示主图区 |
| 店铺、店铺链接、页面地区 | 店铺链接保留公开路由必要参数，去掉跟踪参数，缺失时标明原因 |
| 展示价格、价格数值、价格说明 | 保留“首单价、补贴后、优惠后”等条件；不是最终结算价；无法识别单一数值时保留原文 |
| 销量提示原文 | 保留“4万+人付款”“1万+人收货”等文字，也可能是“本月行业热销”等提示；不转换成精确销量或月销量 |
| 商品 ID、商品链接 | 详情直链去除跟踪参数；推广链接 ID 交叉核对后才采信，生成的普通入口会标明未打开验证；不能确认时留空 |
| 关键词、第一页、展示位置、时间、批次、排序 | 有商品时必须确认“销量”，排序不明则暂停；明确空结果时允许无排序，另作标记 |
| 广告标记、字段缺失、备注 | “未识别广告标记”不代表非广告，不据此判断自然排名 |
| 榜单名称/名次、属性标签、优惠服务标签 | 保留原文；榜单名次不作为搜索位置 |
| 视频标识、视频链接、图标链接 | 图标与视频文件分别保存；有播放图标但无视频地址时记为页面未提供 |
| 原始格子位置、连续商品序号 | 跳过调查卡后仍能对应原页面位置，同ID不同展示位分别保留 |

用户已确认两份 DOM 字段清单，新版从 `#content_items_wrapper` 的直接子格子读取。广告图片命中时 CSV 的“广告推荐位”显示“是”，“广告识别依据”记录命中原因；图片 URL 和选择器见 [单商品 DOM 字段清单](淘宝单商品DOM字段清单.md)。未命中该图显示“未检测到指定标记”，不推断为自然排名。

每次任务生成新批次，保留历史。同一商品在不同展示位分别保留；已确认调查卡，以及同时具有 `suggestItemCard--` 结构和“大家都在搜”标题、且没有商品入口的推荐词卡，单独统计并跳过，不占商品数量。不点击调查评分或推荐词。采集范围内未知内容、商品 ID 冲突或缺少标题/展示价格时暂停，不静默略过。只有页面明确显示无结果，才保存空结果。

CSV 的“字段状态说明”区分页面未提供、元素或内容未识别、不适用，缺失值不填成 0。JSON `counts` 记录全页已加载格子的分类数量及本批导出数量，其中 `search_suggestions_count` 为推荐词卡数量；广告和破损商品作为商品子集统计，不重复加进格子总数。未传上限时 `requested_limit=null`，正常采完当前页记为 `all_loaded_cards_collected`；显式限制时，上限之后的未知格子记录在 `issues` 中，范围内的未知项仍会暂停。

CSV 的“采集时间”统一转换为北京时间，格式为 `YYYY-MM-DD HH:mm:ss`，例如 `2026-10-21 13:14:02`；同一批页面快照的商品共用采集时间。JSON 保留原始带时区的 ISO 时间，例如 `2026-10-21T05:14:02+00:00`。此规则适用于新导出的 CSV，已有历史文件保留原样。

JSON 中 `requested_sort="sales"`、`sort_label="销量"`、`sort_status="confirmed"` 表示已确认平台销量排序；空结果无需排序时记为 `not_applicable_empty_results`。平台展示的销量排序不保证每条提示都可比较为精确数字，也不排除广告，因此不在本地猜测销量数值后重新排列。

| 输出 | 项目内位置 |
|---|---|
| JSON，含批次信息、字段原文及核对依据 | `workspace/output/raw/taobao_products/<批次编号>.json` |
| 中文 CSV，可用 Excel 打开 | `workspace/output/raw/taobao_products/<批次编号>.csv` |
| 采集现场截图 | `workspace/logs/screenshots/taobao-collection-<批次编号>.png` |
| 动作与验证事件 | `workspace/logs/taobao/<任务编号>.jsonl` |

CSV 使用 UTF-8 BOM，标题、店铺等文本如以公式符号开头会加文本前缀；超过 15 位的商品 ID 也加前缀，避免表格软件误执行或损失精度。JSON 保留原值。

遇到验证、登录失效、未知弹窗或采集中关键词、页码、排序变化时，保留当前窗口并提示人工处理。处理后在原终端输入 `继续`；无法输入时在另一个终端执行 `taobao continue`。复核通过才继续，不重新搜索。`taobao pause`、`taobao stop` 以及原生弹窗的确认/取消命令同样适用；停止不会删除已经保存的批次。

2026-10-21 实测：同一“粘毛器”第一页加载 46 张卡片，读取并保存前 20 件，商品 ID、标题、价格、店铺和付款人数原文均已识别。本次排序未识别并已标记，广告标记均为未识别；未跟随推广链接或访问详情。

## 淘宝单商品详情页入口（PowerShell）

同一个 `--input` 参数接受两种输入：纯数字按商品 ID 拼接固定地址，完整详情链接校验后按原链接打开。示例：

```powershell
cd D:\VSCodeProject\taobao_automation_system
# ID 方式：打开 https://item.taobao.com/item.htm?id=1007759256325
.\.venv\Scripts\python.exe main.py taobao detail --input "1007759256325"
# 链接方式：直接使用输入链接打开
.\.venv\Scripts\python.exe main.py taobao detail --input "https://item.taobao.com/item.htm?id=1007759256325"
```

默认打开详情页入口并保留窗口供 DOM 字段核对。加 `--video` 下载主图视频，`--main-images` 下载五张主图，`--skus` 采集标题、售出件数、SKU价格和图片；可分别或组合启用。图文详情等其他字段及列表循环仍待接入。入口记录状态为 `opened_pending_dom_review`，只证明入口打开；各采集步骤结果另存于商品 JSON。

```powershell
.\.venv\Scripts\python.exe main.py taobao detail --input "1050158363561" --video
```

视频步骤只检查用户指定的主图画廊 `#picGalleryEle`，主视频节点为 `#mainPicVideoEl video`，类名前缀选择器作为同一区域的兼容定位。确认画廊已加载并选中首个缩略图；已有视频直接读取播放器的 `currentSrc` / `src` / `<source>`。当前支持下载普通 MP4 直链，保存前校验文件头、响应类型和完整长度。视频播放地址原样记录到本地结果，日志不输出带签名参数的媒体链接。

- 无视频：确认主图画廊已加载，首个槽位无视频节点或标识后，返回“无视频，已跳过主图视频采集”，不发起媒体下载。
- 有视频但地址未取得、结构不明或页面未加载完成：暂停人工核对；不能作为无视频跳过。
- `blob` 等非直链、格式暂不支持或下载失败：明确记录为有视频但未下载，保留原因，不自动重试，不标成无视频。
- 下载时按分段检查守卫，支持人工暂停及停止；视频文件按“商品ID + 真实格式扩展名”命名，当前为 `<商品ID>.mp4`，异常或停止清理本次未完成的 `.part`。
- 最新详情资料集中在 `workspace/output/raw/taobao_details/<商品ID>/`：视频为 `<商品ID>.mp4`，统一详情 JSON 为 `<商品ID>.json`。视频结果保存在 JSON 的 `video` 分区，含有无视频、状态、原链接、相对文件名 `video_file`、本地路径、字节数、SHA-256、页面提供的时长和采集时间；后续其他资料分区合并到同一 JSON，保留已有字段。
- `history/<批次编号>/` 保留每次的原视频和 `video.json`，重复采集只更新商品目录中的最新资料，历史批次保留。无视频时保存 JSON 并跳过视频文件；若之前存在视频，其历史原件仍保留，最新目录不沿用旧视频。
- 本步骤完成后默认保留详情页，等待下一批字段要求；`--no-wait` 则关闭窗口。不会自动采集其他详情字段或进入其他商品。

规则如下：

- 纯数字 ID：去掉两端空格后，拼接 `https://item.taobao.com/item.htm?id=` 加原 ID。须为 1～25 位正整数。
- 详情链接：支持 `http/https` 的 `item.taobao.com/item.htm` 和 `detail.tmall.com/item.htm`，须有唯一有效 `id`。打开时保留输入链接的规格和其他查询参数；入口记录仅保存去跟踪参数的商品地址。
- 沿用淘宝独立浏览器资料和登录状态，与搜索采集共用串行任务锁；先结束上次保留的测试任务后再运行。单次导航使用 `page` 间隔，默认 4～8 秒；验证或异常暂停待人工，不自动重开或刷新。
- 保存入口 JSON 到 `workspace/output/raw/taobao_detail_open/<任务编号>.json`，截图到 `workspace/logs/screenshots/taobao-detail-open-<任务编号>.png`，默认保留窗口；加 `--no-wait` 则保存入口记录后关闭。
- 关闭详情标签页可结束任务；验证后的 `继续` 和 `taobao continue`、`pause`、`stop`、`confirm`、`cancel` 沿用现有机制。

### 采集标题、售出件数、SKU价格和图片

```powershell
.\.venv\Scripts\python.exe main.py taobao detail --input "1050158363561" --skus
```

程序动态识别商品规格组与选项数量，逐项选择 SKU；多组规格按完整组合选择并核对联动状态。购买数量须为1，其他数量提示人工修正。确认选中状态、价格加载和相关请求结束并稳定后读取，不要求相邻 SKU 的价格不同，不自动重试点击。当前只适配已核对的 `#skuOptionsArea` 规格区域；缺少区域、选项身份变化或价格不明时暂停人工核对，不当作无SKU或无货。

图片保存到 `workspace/output/raw/taobao_details/<商品ID>/sku图/<SKU名称>.<真实格式>`，多规格名称包含完整属性组合。SKU共用图片时仍各存一份；无货SKU有图片也保存。优先使用页面提供的大图或与SKU图片匹配的当前主图，否则保存该选项实际提供的图片并记录来源，不拼接大图链接。名称中的Windows非法字符作必要替换，保留JSON原名称；重名增加唯一后缀。未显示图片与下载失败分别标记。

商品JSON新增 `product_info`（标题、售出件数原文及数值口径、评价/回头客/加购提示、时间）和 `sku_details`（规格组、SKU名称、规格值标识、页面明确提供的SKU ID、价格、币种、价格标签、状态、图片链接/路径/尺寸/哈希及完整性统计）。金额数值以十进制字符串记录以保留精度。`已售10万+`只记录销量下限，不当作精确销量或月销量；“优惠前”按原标签记录，不当作券后价。

明确无货的SKU价格默认填写 **“当前缺货，无法识别价格”**，`price_value=null`；仅禁用而无明确缺货依据的标记为原因未确认，价格留空。该SKU仍保留在结果中。汇总显示候选/已确认数量、价格成功数、缺货数、图片成功/失败/无图片数。

每批原件在 `history/<批次编号>/sku图/` 和 `sku_details.json`。每项先存价格进度，中途停止保留 `sku_progress.json`，不会将未完成记录报为成功；当前不自动续跑上次业务。完整批次原子发布商品目录最新图片与JSON，保留视频和主图；部分失败仅保存最后尝试和历史，不覆盖此前完整结果。完成后保留页面等待下一步；加 `--no-wait` 结束所选步骤后关闭。

## 参数代表什么

商品参数加在 `product open` 后面。文件和目录路径、带空格的文本都放在双引号中。

| 参数 | 含义 |
|---|---|
| `--keyword "粘毛器"` | 发布页搜索词 |
| `--category "完整类目路径"` | 用 `>` 分隔的完整类目；需要搜索词 |
| `--brand "无品牌/无注册商标"` | 选择品牌并进入填写页；需要类目 |
| `--main-images-dir "目录"` | 上传目录中的五张 1:1 主图 |
| `--portrait-images-dir "目录"` | 上传目录中的五张 3:4 主图 |
| `--detail-images-dir "目录"` | 按数字编号上传全部详情图 |
| `--video-file "文件.mp4"` | 上传商品视频，可省略 |
| `--product-info-file "文件.xlsx"` | 读取固定格式 Excel，填写分类、两个标题、五个属性、SKU、价格及编码；启用多件优惠，选择放入仓库 |
| `--sku-images-dir "目录"` | SKU图片目录，可省略；默认 Excel 同目录下的 `sku图`，需同时提供 Excel |
| `--submit` | 填写后点击提交到仓库；需要品牌及 Excel。不加时只填写 |
| `--no-wait` | 正常完成后自动关闭浏览器；中途人工提示仍会等待 |
| `--start` | 旧页面“开启”按钮兼容参数，尚未完成真实验证，正常流程不用 |
| `--port 8000` | 工作台端口，只用于 `web` 命令 |
| `--config "配置.toml"` | 指定配置文件，放在 `account`、`product` 等子命令之前 |

素材上传和 Excel 参数都需要先提供品牌，以进入商品填写页。Excel 使用现有固定格式的 `Sheet1`，运行前保存文件。

SKU 自动逐条填写：**SKU搜索主图、商品规格图片**共用同名图片（文件名去扩展名须等于完整销售规格名，扩展名不限）；**SKU搜索标题**使用 Excel 的“导购标题”。缺图、缺标题或未找到页面规格时，跳过对应字段并写明日志，其他可填字段继续；同名多图不猜选，页面已有图片保留并记录。

## 遇到弹窗怎么办

以上千牛命令已自动启用全局检测，无需增加参数；正常图片、视频、规格窗口按原流程使用。
主图、详情图和 SKU 图片上传期间会持续接管文件选择请求，防止额外的系统“打开文件”窗口；无需新增命令或参数。

| 提示 | 你的操作 |
|---|---|
| 已识别的“SKU管理页引导”公告 | 程序自动关闭；关闭失败则转人工 |
| 系统验证、未知弹窗或意外标签页 | 听到提示音后手动处理，在同一个 CMD 输入 `继续` 回车；没有反馈一直等待，弹窗仍在则继续等待 |
| 浏览器原生确认框 | 阅读终端中的内容，输入 `确认` 或 `取消` 回车；输入 `继续` 不会作出决定 |
| 当前等待或填写步骤超时 | 手动关闭弹窗后输入 `继续`，程序在当前浏览器恢复这个子步骤，完成后接着执行；已上传的素材不会重新上传 |
| 商品提交检查 | 人工核对页面和仓库后输入 `继续`，程序只复核结果，避免重复提交 |
