## 浏览器环境与操作节奏

- 淘宝和千牛各用一套独立的浏览器资料，分别复用自己的登录状态；两个平台可以使用相同或不同的账号，不要求账号相同。
- 浏览器版本、语言、时区、视口等使用相互一致的设置；不在任务执行中随意切换环境或每次随机更换指纹。
- 默认有界面、单任务、串行操作；通过正常页面入口搜索、滚动和翻页。
- 等待页面及商品列表实际就绪，再加入可配置的操作间隔和小幅随机停顿；固定睡眠不能替代页面就绪判断。
- 商品数量仅在显式指定 `--limit` 时限制；滚动、短等待等操作仍有上限，避免停滞时无限循环。翻页尚未接入。
- 频控、访问异常或重复验证出现后降低频率或暂停，不紧密循环刷新或重试；人工等待期间不发起后续业务操作。

## 人工验证和弹窗

- 搜索、滚动、翻页、读取及保存前后设置检查点，长时间等待时也持续检查。
- 登录失效、滑块、验证码、安全验证、访问受限、未知遮罩、未知弹窗及意外新标签页都应暂停。
- 不自动完成安全验证；未知弹窗不盲目点击“确定”或关闭。正常商品业务弹窗仅在明确识别后按已定义流程处理。
- 暂停时保留同一浏览器和页面，记录任务编号、关键词、当前步骤、进度、触发时间、类型及截图路径；响一次提示音并说明需要用户做什么。
- 等待人工处理不设超时，不自动关闭浏览器，不重启登录，不刷新二维码；无反馈一直等待。
- 用户处理完后须明确回复“继续”，由运行任务的输入通道接收；空回车、时间流逝、弹窗自行消失都不能放行。
- 在聊天中运行时，助手将用户明确的“继续”转交给等待中的任务，而不是另起任务。
- 收到“继续”后，重新确认阻断已解除、登录仍有效、页面和搜索条件符合当前步骤；没有通过则继续暂停，同一次阻断不反复响铃。
- 浏览器原生确认框必须提示实际内容并由用户明确选择确认或取消；通用“继续”不能替代该决定。
- 人工等待时长不计入普通页面操作超时。完成后恢复当前未完成步骤，不重新执行整轮搜索和翻页。
- 用户关闭浏览器或取消时保留已有数据并明确记录结束原因；输入通道丢失时不视为收到继续指令，并提供可见的人工处理状态。

## 数据与恢复

- 每批结果及时保存，并记录关键词、排序方式、页码或批次、展示位置、时间以及已完成步骤。
- 同一商品 ID 在不同展示位分别保留，记录原始格子位置和连续商品序号；不同批次保留历史。缺少可靠商品 ID 的记录须转人工核对，不能猜测合并。
- 恢复前确认上次点击是否已经生效、列表是否已经加载，避免重复点击下一页、跳过一页或重复计数。
- 区分正常无结果、正常加载结束、页面未加载完成、登录失效、验证拦截和解析失败；不能把后几种记录为“零商品”或成功完成。
- 页面字段缺失或结构变化应明确记录；保留展示价格的条件、销量原文及广告标记的识别状态，不把展示值当成精确成交指标。
- 日志不写入 Cookie、Token、密码、完整手机号或带授权参数的网址。现场截图仅保存到本地运行目录，不提交版本库。

## 验证与下一阶段

淘宝专用守卫已用本地测试页面验证以下暂停和恢复行为，关键词搜索继续在该守卫下验证：

1. 出现阻断后记录现场、提示一次，且不再执行后续步骤。
2. 弹窗自行消失但用户尚未回复时，仍然等待。
3. 收到“继续”但验证仍存在时，保持暂停。
4. 明确反馈且页面复核通过后，从当前步骤恢复，不重复业务操作。
5. 暂停较长时间后仍可恢复，已有采集数据不丢失。
6. 关闭浏览器、输入通道关闭或任务取消都不会被误判为继续或采集成功。

真实页面仅在自然遇到验证时验证人工流程，不主动制造风控。

## 补充措施与实施顺序

以下区分已接入的保护和采集阶段仍需完善的部分。

### 已接入登录流程及保护组件

- 提供统一的运行、暂停待人工、恢复检查、停止状态；人工暂停时冻结程序的后续翻页、业务重试及任务调度，避免前台等待而后台继续采集。已发出的请求可能仍会返回，须标记其所属步骤，不据此自动推进。
- 在浏览器正常访问过程中被动观察主页面和商品列表相关请求的响应，辅助识别访问拒绝、限流和网络失败；第三方广告、统计或图片的单个失败不能直接判定淘宝封禁。
- 若相关响应带有 Retry-After，记录并遵守其等待期限。该期限结束不等于人工批准；已进入待人工状态的任务仍须收到“继续”并复核通过后恢复。
- 同时检查可见页面；HTTP 成功响应仍可能展示登录或验证页面，不能只依据状态码推进。
- 提供人工暂停或停止入口。停止后先保存已有进度和结果，再有序退出；不得误报完整采集成功。

主页面监听已接入；商品列表请求需要搜索模块登记后才会参与限流判断。守卫不能识别所有未知页面结构，出现无法确认的页面时按需人工处理。

### 接入采集后逐步完善（尚未实现）

- 同批次内复用已读取的结果，减少重复加载；明确区分恢复旧批次和发起新批次。新批次仍保留新的采集时间，避免缓存旧价格冒充新结果。
- 第一版仅采搜索列表中所需字段；后续仅对筛选后的候选商品打开详情页，减少无效访问。
- 每次记录操作数量、等待耗时、相关请求失败、验证触发次数及商品解析完整度，用于调整访问上限和间隔，不通过高频访问去寻找风控阈值。
- 浏览器和依赖升级后先做小规模回归，确认登录及人工恢复仍可用，再扩大采集；保留版本记录便于定位变化。
- 用本地测试页面模拟验证、延迟、限流响应、异常新标签页及暂停期间返回的请求，验证状态和恢复顺序。

## 当前使用方式

```powershell
python main.py account login --platform taobao
python main.py account check --platform taobao
python main.py taobao search --keyword "粘毛器"
```

这些命令自动安装淘宝守卫。提示后在运行该任务的终端输入“继续”；空回车和“已完成”均不放行。若由助手运行，可在聊天中回复“继续”，由助手转交正在等待的任务。输入“停止”结束当前任务。原生弹窗需先明确输入“确认”或“取消”，之后再输入“继续”恢复后续步骤。同一个阻断不反复响铃，出现新的独立阻断会再次提示。

在另一个终端控制当前淘宝登录或搜索任务：

```powershell
python main.py taobao pause
python main.py taobao stop
python main.py taobao continue
python main.py taobao confirm
python main.py taobao cancel
```

控制请求在下一检查点接收，不会启动第二个浏览器。继续、确认和取消指令与当前提示编号绑定，旧反馈不会放行新的验证，也不允许使用继续代替原生弹窗决定。进入人工等待后仍可接收停止请求；收到停止指令时结束任务，不视为采集成功。输入通道关闭时，有人工入口的任务保留现场并等待上述独立反馈通道；无人工入口则返回需要人工处理。

每次任务的事件记录位于 `workspace/logs/taobao/<任务编号>.jsonl`，现场截图在 `workspace/logs/screenshots`。任务数据库在暂停时显示“需人工处理”，恢复后显示“运行中”；人工等待不会填写任务结束时间。

`[taobao.pacing]` 支持 `before_search`（提交前）、`search`（结果加载后）、`scroll`、`page`、`keyword` 五种动作的最小/最大秒数，默认分别为 `[2,4]`、`[2,4]`、`[1.5,3]`、`[4,8]`、`[8,15]`。提交前等待结束后重新核对关键词和按钮状态。登录不会无意义地等待这些间隔；这些初始参数不代表能避免平台验证。

后续淘宝业务统一复用 `platforms.taobao.session.browser_session`，动作前后调用守卫检查，长等待使用守卫的分段等待；操作不得绕过守卫自行循环重试。恢复检查由业务提供当前页面、搜索条件及登录状态的只读判定，不能为了复核而重新执行整轮搜索。

## 浏览器环境对照（2026-10-21）

### 本地启动和连接对照

- 本机临时资料、本机测试页实测：系统 Chrome 普通启动的 `navigator.webdriver=false`；仅增加 `--enable-automation` 后为 `true`；普通启动增加非零本机调试端口后连接 Playwright，该值在连接前后均为 `false`；原 Playwright 默认启动为 `true`。测试不读写淘宝资料、不访问淘宝，也不改写这些浏览器属性。
- 原默认启动的实际参数包含 `--remote-debugging-pipe`、多项默认功能开关和 `--no-sandbox`；当前安装版本没有默认传入 `--enable-automation`。因此不能把“删除 enable-automation 参数”宣称为本项目修复方案。实际命令行仅从本次临时测试进程读取，报告中临时目录被替换。
- 本地对照中，程序连接还改变了页面的可见性表现；UA、语言、时区等所测字段一致。这些是可观测差异，不是淘宝服务端判断依据的证明。Playwright 驱动核心文件和生成的 Python API 与本机安装记录中的校验值一致。
- 详细数据在 `workspace/output/reports/browser_launch_comparison_20261021.json`。现场单参数对照已完成：成功的普通启动入口仅增加 `--enable-automation`，不连接程序、不读取或点击页面，用户仍复现验证，且手动验证失败。这说明本次复现不需要程序点击或 DOM 扫描参与；尚不能证明淘宝只检查某一个字段。
- 继续现场对照：普通启动仅增加非零本机调试入口、不连接程序，用户确认搜索正常；随后通过 CDP 连接同一窗口，设置 `no_defaults=True` 保留浏览器既有默认设置，不主动读取或操作页面，用户再次确认搜索正常。连接本身在本次条件下未复现失败。

### 普通启动连接候选路径

- `[taobao] browser_channel="chrome"` 配合 `browser_mode="native_cdp"` 可选择普通系统 Chrome 启动，再从本机连接。`browser_mode` 默认仍为 `playwright`；千牛入口不使用此模式。当前候选仅支持可见的系统 Chrome。
